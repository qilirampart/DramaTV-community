# 发给后台 Codex 的共享联动接手提示词

你现在继续的是 DramaTV 社区项目里的“管理后台 + 共享后端”这条线。

先不要直接开始写代码，先按下面顺序读取并建立上下文：

1. `E:\点众\DramaTV社区搭建\AGENTS.md`
2. `E:\点众\DramaTV社区搭建\.codex\community-admin-shared-sync.md`
3. `E:\点众\DramaTV社区搭建\.codex\progress-admin.md`
4. `E:\点众\DramaTV社区搭建\.codex\progress.md`

其中最重要的是第 2 个文件：

- `E:\点众\DramaTV社区搭建\.codex\community-admin-shared-sync.md`

尤其先看里面的：

- `4A. 当前后台已真实落地的共享能力地图`
- `4B. 当前前台已真实消费的后台字段 / 状态`

这份文件从现在开始是：

- 社区前台 `apps/web`
- 管理后台 `apps/admin`
- 共享后端 `apps/server`

之间“会互相影响的真实链路”的单一事实源。

你的工作规则如下：

## 1. 先看共享台账，再做共享改动

如果你的改动会影响以下任一项，就不能只看 `progress-admin.md`，必须先看共享台账：

- 前后台共用接口
- 前后台共用状态语义
- 数据库字段变更，且前台也会消费
- 后台操作会影响前台真实展示
- 前台依赖后台治理配置的链路
- 举报、审核、taxonomy、feed-ops、媒体任务、发布生命周期这类共享链路

## 2. 更新顺序固定

只要你改的是共享链路，更新顺序必须是：

1. 先更新 `community-admin-shared-sync.md`
2. 再更新 `progress-admin.md`
3. 如果需要，再在 `progress.md` 留全局索引

不要反过来。

原因很简单：

- `progress-admin.md` 记录的是后台线自己的进度
- `community-admin-shared-sync.md` 记录的是前后台共同依赖的真实口径

## 3. 不要自己猜前台契约

如果你要改共享接口、状态字段、返回结构、筛选 key、治理动作语义，不要只根据后台页面当前写法猜。

先检查：

- 共享台账里有没有现成口径
- `apps/web` 当前有没有已经消费的契约
- 这次改动是否会让前台出现“页面没报错，但语义已经错了”的隐性回归

## 4. 共享项必须按统一模板补记录

后续你新增共享项时，按共享台账里的模板补，至少写清楚：

- 状态：`planned / in_progress / implemented / verified`
- 影响范围：前台 / 后台 / 后端
- 当前真实口径
- 前台状态
- 后台状态
- 验证状态
- 风险 / 未对齐点

不要只写“已完成”。

## 5. 当前你要特别注意的共享项

当前共享台账里已经明确收口过的重点有：

- `S1` 发布生命周期语义
- `S2` 举报提交 -> 后台工单
- `S3` 审核/下线动作 -> 前台可见性
- `S4` taxonomy 分类体系
- `S5` feed-ops 运营编排
- `S6` 媒体任务 / 上传 / 任务可见性

当前明确还没完全收口的重点有：

- `U1` 审核动作到前台展示的自动回归
- `U2` taxonomy 新增分类流程制度化
- `U3` feed-ops / taxonomy / moderation 的共享验收口径统一

## 6. 你的默认工作方式

你继续做后台线时：

- 纯后台样式问题，记 `progress-admin.md`
- 纯后台独立实现细节，记 `progress-admin.md`
- 只要会影响社区前台理解、联调或验收，优先更新 `community-admin-shared-sync.md`

## 7. 当前目标

你的目标不是只把后台页面做出来，而是：

- 让后台治理动作和社区前台真实行为安全联通
- 减少前后台信息差
- 避免“后台已经改了，但前台不知道”或“前台已改契约，后台还按旧逻辑继续开发”的无效工作

看完上述文档后，再开始继续当前后台开发任务。
