## 3. 当前项目状态

### 3.1 已完成的大方向

- 社区前台主线页面基本完成
- 社区前台主线为 `Next.js + React + TypeScript`
- 社区后端主线为 `Spring Boot`
- 本地社区前台、后端、数据库、Redis 已基本形成闭环
- 社区内容三类口径已经收口：
  - `视频提示词`
  - `图片提示词`
  - `工作流内容`
  - 另有独立的 `帖子`
- 登录、点赞、收藏、评论、楼中楼、个人中心、发布等社区主链路基本已打通

- `apps/admin` 已补独立 `package-lock.json`，`tsc` 与正式 `next build` 都已验证通过
- 后台接口 `/api/admin/**` 已落第一批真实接口：`auth + users`
- 当前最优先的真接口顺序固定为：`/api/admin/moderation -> /api/admin/reports -> /api/admin/comments`

- 不是继续返工社区前台大页面

## 6. 视觉与交互规则

这些规则已经在这轮对话中明确过，新聊天不要跑偏。

### 6.1 风格规则

- 整体走 `白底 + 黑灰色系`
- 中文优先，页面尽可能中文
- 品牌名 `DramaTV` 可保留英文
- 不要紫蓝科技风
- 不要赛博朋克
- 不要通用 SaaS 模板感
- 不要花哨大屏感
- 要高级、克制、专业、可落地

### 6.2 组件感觉

- 弱化边框感
- 不要一个模块一个厚重框
- 多通过留白、层级、轻阴影、排版来分区
- 表格、弹窗、抽屉都要显得轻、整洁、长期可用

### 6.3 页面语言

- 登录页极简，不要塞太多信息
- 总览页信息可以多，但仍要整洁
- 用户管理、审核、举报、评论、运营、分类、媒体任务、日志要各有业务重心
- 弹层不是独立页，要有明显的“挂在后台页面上”的感觉

## 7. 当前推荐推进顺序

当前 `apps/admin` 的 Phase 1 和页面骨架阶段已经完成，新聊天不要再回头重搭。继续推进时建议按下面顺序：

### Phase 3：继续把治理链路接起来

1. 落 `/api/admin/moderation`
2. 落 `/api/admin/reports`
3. 落 `/api/admin/comments`
4. 保持 `admin / operator / moderator` 这套最小 RBAC 不漂移

### Phase 4：再补 4 个关键交互层

1. 用户编辑 / 重置密码弹窗
2. 审核详情抽屉
3. 举报处理弹窗
4. 运营挂载 / 排序弹窗

### Phase 5：再向其他运营模块扩展

1. `/feed-ops/**`
2. `/taxonomy`
3. `/media-tasks`
4. `/audit-logs`

不要因为接口未完成就退回“只做文档分析”，但也不要跳过 `moderation/reports/comments` 直接分散接所有后台页。
