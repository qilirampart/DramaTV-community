# 测试环境稳定版本管理补充

日期：`2026-05-19`

适用范围：

- 社区前台 `apps/web`
- 社区后端 `apps/server`
- 管理后台前端 `apps/admin` 已自 `2026-05-21` 起单独纳入测试环境云发布，详见 `测试环境管理后台云发布补充-2026-05-21.md`

## 1. 当前第一版稳定基线

这轮已经把云侧当前版本固化成第一版稳定基线：

- 稳定标识：`test-stable-2026-05-19-community-r1`
- 前端 current：`/opt/dramatv-community-web/releases/20260509-141400`
- 后端 current：`/opt/dramatv-community-server/releases/20260509-123834`
- 稳定版本台账：`ops/releases/test-env-release-ledger.md`
- 远端元数据状态：已通过 `scripts/stamp-test-stable-baseline.ps1` 回填 `release.json`

说明：

- 这组 release 是“补 release 元数据之前”的历史云端现态
- 因此当前只把它记作 `legacy baseline`
- 后续所有新发布都以它作为回滚锚点

## 2. 这轮新增的标准入口

### 2.1 标准部署

```powershell
npm run deploy:test:web
npm run deploy:test:backend
```

默认行为：

- 自动跑部署前验证
- 执行测试环境部署
- 自动跑部署后最小可用性检查

### 2.2 查看测试环境 release

```powershell
npm run release:list:test
```

用途：

- 看当前 `current` 指向
- 看近几次 `web / server` release
- 确认回滚目标

### 2.3 一次性补盖稳定基线元数据

```powershell
npm run release:stamp:baseline:test
```

用途：

- 给历史云端 current release 回填 `release.json`
- 把“第一版稳定版本”从本地台账推进到远端 release 目录

### 2.4 标准回滚

```powershell
npm run rollback:test:web -- -ReleaseName <release> -VerifyAfterRollback
npm run rollback:test:backend -- -ReleaseName <release> -VerifyAfterRollback
```

说明：

- `<release>` 使用 `release:list:test` 输出里的 release 名称
- `-VerifyAfterRollback` 会在回退后补一次最小验收

## 3. 新增的 release 元数据

从这轮开始，新的测试环境发布会在远端 release 目录自动写入：

- `release.json`

当前记录字段包括：

- `releaseName`
- `releaseLabel`
- `component`
- `sourceMode`
- `branch`
- `commitSha`
- `commitShortSha`
- `dirtyWorkspace`
- `workspaceStatus`
- `deployedBy`
- `generatedAt`
- `verifyBefore`
- `verifyAfter`
- `releaseNotes`

## 4. 当前阶段的边界

这轮还没有一步到位做完整 CI/CD，当前只先收口到下面这层：

- 测试环境有稳定基线
- 发布有统一入口
- release 有身份信息
- 回滚有固定命令

暂时还没有完全收口的部分：

- 强制只从干净工作区发版
- 强制只从明确 Git commit 发版
- 自动化发布流水线
- 数据库快照级回滚

## 5. 后续建议顺序

1. 后续社区前台云同步优先走 `deploy:test:web / deploy:test:backend`
2. 每次部署前先看 `release:list:test`
3. 重要阶段性版本都补记到 `ops/releases/test-env-release-ledger.md`
4. 下一轮再继续推进“按 commit 发版”和更标准的 CI/CD
