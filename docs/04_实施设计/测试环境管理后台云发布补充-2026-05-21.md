# 测试环境管理后台云发布补充

日期：`2026-05-21`

适用范围：
- 管理后台前端 `apps/admin`
- 社区统一后端 `apps/server`
- 测试云环境中的真实社区前台 / 真实社区后端联动

## 1. 这份补充解决什么问题

之前测试环境的正式发布链路只覆盖：

- 社区前台 `apps/web`
- 社区后端 `apps/server`

管理后台 `apps/admin` 虽然已经是独立正式工程，但还没有纳入同一套：

- release 目录
- `current` 切换
- `release.json`
- 查看 release
- 固定回滚入口

这份补充把管理后台也接入测试环境云发布体系。

## 2. 当前运行策略

当前测试环境先固定为：

- `apps/admin` 作为独立前端运行时单元发布
- `apps/server` 继续复用同一台云机上的统一后端
- 管理后台服务端请求后端时，走内网地址：
  - `DRAMATV_ADMIN_API_BASE_URL=http://127.0.0.1:18080`
- 管理后台浏览器侧解析真实图片、视频、前台静态资源时，走社区公网入口：
  - `NEXT_PUBLIC_DRAMATV_ADMIN_API_BASE_URL=<community public base url>`
  - `NEXT_PUBLIC_DRAMATV_WEB_BASE_URL=<community public base url>`

一句话约束：

- 管理后台页面本身是独立入口
- 真实内容资源仍然以社区公网入口和共享后端为准

## 3. 当前云入口策略

这轮先落地为：

- 管理后台运行在独立服务 `dramatv-community-admin`
- 默认对外验收入口使用独立端口：
  - `http://8.141.20.130:3206`

这样做的原因是：

- 不会和当前社区前台 `80 -> apps/web` 的 Nginx 入口互相覆盖
- 可以先把后台纳入真实云环境联调
- 后续如果正式域名 `admin-community.xxx.com` 就绪，只需要改公开入口参数，不需要重做 release 目录结构

当前没有在这轮脚本里强绑定新的 Nginx 域名配置。

管理后台运行时会直接绑定到 `0.0.0.0:3206`，因此外网能否访问还取决于云机安全组和本地防火墙：

如果当前就按 `http://<公网IP>:3206` 验收，还需要同步确认：

- 云机安全组已放通 `3206`
- 机器本地防火墙没有拦截 `3206`

## 4. 新增标准命令

### 4.1 发布

```powershell
npm run deploy:test:admin
```

默认行为：

- 先执行 `deploy:verify:pre`
- 打包 `apps/admin` 源码并上传到云机
- 在远端 `releases/<timestamp>` 执行 `npm ci` 和 `npm run build`
- 切换 `current`
- 重启 `dramatv-community-admin`
- 运行管理后台 smoke 作为部署后最小验收

### 4.2 查看 release

```powershell
npm run release:list:test -- -Runtime admin
```

当前 `release:list:test` 已支持：

- `web`
- `server`
- `admin`
- `all`

### 4.3 回滚

```powershell
npm run rollback:test:admin -- -ReleaseName <release> -VerifyAfterRollback
```

默认行为：

- 把 `current` 切回目标 release
- 重启 `dramatv-community-admin`
- 可选执行管理后台 smoke 验证

## 5. 管理后台 release 结构

远端目录固定为：

```text
/opt/dramatv-community-admin/
  releases/<timestamp>/
  current -> releases/<timestamp>
  shared/dramatv-community-admin.env
```

每次新发布都会在对应 release 目录写入：

- `release.json`

字段口径与社区前台 / 社区后端保持一致。

## 6. 当前部署后验收口径

管理后台云发布后的最低验收固定为：

1. 公网入口 smoke：
   - 从本地执行 `scripts/smoke-admin-routes.mjs --mode public`
   - 验证 `http://8.141.20.130:3206` 的登录页可访问
   - 验证受保护页匿名访问会跳 `/login`
2. 云机内网 smoke：
   - 在云机内执行 `scripts/smoke-admin-routes.mjs --mode full`
   - 页面入口走 `http://127.0.0.1:3206`
   - 后端登录接口走 `http://127.0.0.1:18080/api/admin/auth/login`
3. 登录后以下页面至少返回真实 HTML：
   - `/dashboard`
   - `/users`
   - `/comments`
   - `/moderation`
   - `/reports`
   - `/taxonomy`
   - `/feed-ops/home`
   - `/feed-ops/featured`
   - `/feed-ops/discussions`
   - `/media-tasks`
   - `/audit-logs`

这样拆分的原因是：

- 管理后台用户入口是公网 `:3206`
- 但后台服务端真实登录链路当前固定复用云机内网后端 `127.0.0.1:18080`
- 因此不能再用“本地脚本直接请求公网 `/api/admin/auth/login`”去判断后台发布是否成功，否则会把架构内本来可用的发布误判成失败

## 7. 后续待补

- 如果后续正式启用 `admin-community.xxx.com`，补 Nginx / 域名映射时，优先保留现有 release 目录、service 名称和 rollback 口径，不重造第二套脚本
- 首次真实 `deploy:test:admin` 成功后，把 admin release 记录追加到 `ops/releases/test-env-release-ledger.md`
