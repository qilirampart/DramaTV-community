# 本地开发标准动作清单

日期：`2026-05-18`

适用范围：

- 社区前台：`apps/web`
- 社区后台：`apps/admin`
- 社区后端：`apps/server`

## 1. 先确认本地依赖

至少确认下面几项已经就绪：

- Docker Desktop 已启动
- 本地 PostgreSQL / Redis 容器可用
- Java 17 / Maven 可用
- Node 依赖已安装

推荐先看：

- `docs/04_实施设计/本地开发环境准备.md`
- `docs/04_实施设计/后端本地数据库启动与建表验证.md`

## 2. 拉起本地基础服务

### 2.1 启动 PostgreSQL / Redis

```powershell
docker compose -f infra/local/docker-compose.yml --env-file infra/local/.env up -d
```

### 2.2 检查容器状态

```powershell
docker compose -f infra/local/docker-compose.yml --env-file infra/local/.env ps
```

期望至少看到：

- `dramatv-postgres`
- `dramatv-redis`

都处于运行态。

## 3. 拉起后端

推荐入口：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/run-server-local-db.ps1
```

如果需要固定用 `18080` 做本地联调，可使用当前仓库现有脚本：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-server-18080.ps1
```

## 4. 拉起前端

### 4.1 社区前台

```powershell
npm run dev:web
```

默认本地口径：

- 前台：`http://127.0.0.1:3106`

### 4.2 社区后台

```powershell
npm run dev:admin
```

默认本地口径：

- 后台：`http://127.0.0.1:3206`

## 5. 先做运行态检查

推荐先跑本地 readiness：

```powershell
npm run readiness:local
```

如果只想先看后端：

```powershell
npm run readiness:local:backend
```

## 6. 完成功能后最少要跑什么

### 6.1 日常默认动作

```powershell
npm run verify:quick
```

这套会覆盖：

- 前台与后台 typecheck
- 后端关键集成测试
- API smoke
- 登录 / 会话 smoke

### 6.2 阶段性验收前

```powershell
npm run verify:full
```

这套会额外覆盖：

- 前台与后台 build
- 浏览器级 smoke

## 7. 如果本地数据被测试污染

可以用当前已有脚本回基线：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/reset-local-browser-smoke-state.ps1
```

相关说明见：

- `docs/04_实施设计/本地 smoke 数据重置.md`

## 8. 本地开发完成的最低标准

满足下面 4 条，才算这轮改动可继续往下走：

1. 本地服务能正常打开
2. `npm run readiness:local` 通过
3. `npm run verify:quick` 通过
4. 如果改动影响页面主链路，再补一轮最小人工验收
