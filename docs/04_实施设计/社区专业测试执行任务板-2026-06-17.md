## 1. 目标

把外部“专业测试 skill”包的方法论正式映射到 DramaTV 社区项目，形成可持续执行的测试闭环，而不是只做零散手工点点看。

本轮测试目标分三层：

1. `UI / E2E`
   - 覆盖登录、首页、精选、讨论区、详情页、作者页、个人中心、发布页。
   - 重点抓深滚动、分类切换、返回定位、多跳路由、登录态一致性。
2. `API / 契约`
   - 覆盖前台读接口、登录会话、作者聚合、精选库存、讨论区、发布链路关键接口。
   - 重点抓真实字段语义、分页 / 游标、空态、错误码和分类混排正确性。
3. `稳定性 / 回归`
   - 复用现有 smoke、readiness、browser、backend integration。
   - 对高风险问题形成“复现路径 -> 验证点 -> 缺陷记录 -> 回归复测”闭环。

## 2. 测试方法映射

| 外部能力 | 本项目落地方式 |
| --- | --- |
| `testcase-skills/规划` | 先按页面和风险维度拆测试板，不直接盲测 |
| `UI-skills/执行` | 云端优先用真实浏览器链路复现，必要时再补脚本化 |
| `api-skills/执行` | 优先复用现有 Node / Maven 集成测试与 smoke |
| `bug-reporter` | 发现问题时统一沉淀到项目文档和进度，不只停留在聊天记录 |
| `progress-reporter` | 每完成一轮测试，把结果回写 `.codex/progress-community.md` |

## 4. 本轮测试分层

### L1 主路径冒烟

- 登录 `/login`
- 首页 `/home`
- 精选 `/featured`
- 讨论区 `/discussions`
- 发布 `/publish`
- 个人中心 `/me`

### L2 高风险交互

- 精选深滚动自动加载
- 精选分类快速切换
- 精选搜索与分类结果一致性
- 精选详情 -> 作者 -> 作者作品详情 -> 逐级返回
- 讨论区帖子详情返回定位
- 作者页查看更多、返回定位、状态保持

### L3 语义与数据正确性

- 精选页不应混入帖子
- 活动分类下不应出现帖子
- 图片 / 视频提示词分类语义正确
- 作者页作品数量与真实发布数据一致
- 标题 / 简介展示策略符合当前产品要求

### L4 稳定性与异常

- 登录页与已登录壳态不冲突
- 返回定位不出现长时间 restoring 卡死
- 深滚动后续加载不失效
- 控制台不出现高频错误

## 6. 第一轮执行顺序

1. 云端 UI：登录、首页、精选、讨论区、作者页、详情页、返回定位。
2. 本地 API：`smoke:api`、`smoke:auth-session`、`backend-test:read`、`backend-test:core`。
3. 汇总问题。
4. 决定是否值得把高风险场景沉淀成声明式自动化 spec。

## 7. 通过标准

1. 主路径可打开且不白屏。
2. 高风险返回定位链路可复现、可判定。
3. 已知问题与新问题能明确区分。
4. 每个失败点都有可复现路径和归档记录。
5. 下一轮可以明确转成修复任务，而不是继续模糊试错。
