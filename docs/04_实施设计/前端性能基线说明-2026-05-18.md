# 前端性能基线说明

日期：`2026-05-18`

## 1. 目标

这一版不追求完整性能平台，只先把当前最容易反复出问题的前台链路变成固定基线：

- 首页
- 精选页分类切换
- 详情页进入再返回
- 评论区交互

## 2. 当前脚本

仓库已新增：

- `scripts/run-local-frontend-performance-baseline.py`

根目录命令已补：

- `npm run perf:frontend:baseline`

输出默认落到：

- `artifacts/frontend-performance/latest/summary.json`

## 3. 当前覆盖项

### O3-1 首页性能基线

检查：

- `/`
- `/home`

当前会记录：

- `domContentLoadedMs`
- `loadEventMs`
- `totalResources`
- `mp4Requests`
- `mountedVideos`
- `domNodes`

### O3-2 精选页压力基线

检查：

- `/featured`
- 分类切换约 20 次

当前关注：

- 分类连续切换后是否产出异常 console error
- `mountedVideos` 是否失控
- `mp4Requests` 是否异常增长

### O3-3 详情页往返压力基线

检查：

- 从 `/featured` 进入详情再返回 3 轮

当前关注：

- 详情往返后 `mp4Requests` 是否异常堆积
- `totalResources` 是否持续放大
- 返回链路是否仍可继续进入详情

### O3-4 评论区交互性能基线

检查：

- 视频详情页评论区
- 展开回复
- 打开回复输入框
- 发送一条回复

当前关注：

- 回复后额外资源请求增量
- 评论区条目数量是否异常回退
- 是否还能维持稳定渲染

## 4. 当前定位

这不是严格意义上的 Web Vitals 平台，也不是 Lighthouse。

这版更偏“项目内高风险交互基线”，目的是：

- 把之前反复出现的卡死、循环跳转、视频重复加载、评论区重拉问题收成可复测脚本
- 让性能优化先从真实高风险路径开始，而不是一上来做大而全平台

## 5. 下一步可以继续补什么

下一轮如果继续扩：

1. 记录更多网络细分指标
2. 接入浏览器 trace / profile artifact
3. 分离本地数据重置与评论写入基线
4. 对 `3107` 和公网链路补独立性能口径
