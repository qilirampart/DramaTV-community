# 后台管理最小 Smoke 与浏览器验收清单

更新时间：2026-05-08

## 1. 目的

这份清单用于收口 `apps/admin + apps/server` 当前后台管理线的最小可用验收。

范围固定为：

- 登录与会话
- 概览台
- 用户管理
- 评论治理
- 内容审核
- 举报中心
- 运营配置
- 媒体任务
- 操作日志

当前目标不是做全量回归，而是确认：

1. 后台主入口都能打开
2. 已声明接真数据的页面都确实优先读取真实数据
3. 关键治理动作至少有一轮真实操作或真实详情链路可走通
4. 不再把明显未完成能力伪装成“像是已经好了”

## 2. 角色与账号

本轮浏览器验收优先使用本地 bootstrap 管理员账号：

- 用户名：`admin-chief`
- 密码：`dramatv-admin-demo`

原因：

- 可覆盖 `admin` 角色下的全部导航与治理页
- 可验证敏感操作页的可达性与链接权限边界

## 3. 验收前置

- 后台前端：`http://127.0.0.1:3206`
- 后台后端：`http://127.0.0.1:18080`
- 本轮已确认：
  - `http://127.0.0.1:3206/login -> 200`
  - `http://127.0.0.1:18080/actuator/health -> 200`

## 4. Smoke 测试点

### 4.1 登录与会话

- `SMK-AUTH-001`
  - 目标：本地管理员可登录后台
  - 步骤：访问 `/login`，输入 `admin-chief / dramatv-admin-demo`，提交
  - 预期：进入后台首页，无报错，无卡死 loading

- `SMK-AUTH-002`
  - 目标：登录后主导航按管理员角色完整展示
  - 预期：可见 `概览台 / 用户管理 / 内容审核 / 举报中心 / 评论治理 / 运营配置 / 分类管理 / 媒体任务 / 操作日志`

### 4.2 概览台

- `SMK-DASH-001`
  - 目标：`/dashboard` 可打开且不再显示静态占位总览
  - 预期：统计卡、待审核队列、最新举报、失败任务、账号关注均能正常渲染

- `SMK-DASH-002`
  - 目标：概览台跳转链路可用
  - 预期：待审核队列、最新举报、失败任务、账号关注、快捷操作的链接都能跳到对应真实页面

### 4.3 用户管理

- `SMK-USERS-001`
  - 目标：`/users` 列表与详情优先读真数据
  - 预期：可打开用户详情侧栏，无“假弹窗”问题

- `SMK-USERS-002`
  - 目标：账号治理表单可正常显示
  - 预期：角色、状态、密码治理区块可见

- `SMK-USERS-003`
  - 目标：密码治理已不是占位按钮
  - 预期：显示真实 `初始化密码` 或 `重置密码` 按钮，而不是“待补”

### 4.4 评论治理

- `SMK-COMMENTS-001`
  - 目标：`/comments` 可打开并展示真实评论列表或真实空态
  - 预期：详情抽屉可打开；失败时不冒充完成态

### 4.5 内容审核

- `SMK-MOD-001`
  - 目标：`/moderation` 可打开并展示真实审核列表或真实空态
  - 预期：详情抽屉、状态筛选、操作入口可见

### 4.6 举报中心

- `SMK-REPORT-001`
  - 目标：`/reports` 可打开并展示真实举报列表或真实空态
  - 预期：详情抽屉与联动入口可见

### 4.7 运营配置

- `SMK-FEEDOPS-001`
  - 目标：`/feed-ops/home` 可打开并展示真实配置页
  - 预期：候选池、运营槽位、保存入口可见

- `SMK-FEEDOPS-002`
  - 目标：`/feed-ops/featured` 与 `/feed-ops/discussions` 可打开
  - 预期：两页都不再是纯参考壳

### 4.8 媒体任务

- `SMK-MEDIA-001`
  - 目标：`/media-tasks` 可打开并展示真实任务列表或真实空态
  - 预期：详情面板可打开，失败/重试信息可见

### 4.9 操作日志

- `SMK-AUDIT-001`
  - 目标：`/audit-logs` 可打开并展示真实日志列表或真实空态
  - 预期：详情面板可打开，操作元信息可见

## 5. 本轮不纳入强制动作验收的点

以下页面本轮以“页面可打开、真实数据或真实空态可确认”为主，不强制重复触发写操作：

- 评论隐藏 / 恢复 / 删除
- 审核通过 / 驳回 / 下线 / 恢复
- 举报处理 / 下线联动
- taxonomy 可写治理
- feed-ops 保存
- media-tasks 重试

原因：

- 这些动作前面已经做过代码级验证或定向测试
- 本轮目标是收口后台整体最小 smoke 与浏览器级主路径

## 6. 通过标准

本轮后台最小 smoke 通过需同时满足：

1. `SMK-AUTH` 全部通过
2. `SMK-DASH` 全部通过
3. 其余核心治理页都至少通过“可打开 + 真实数据或真实空态可确认”
4. 未出现新的“静态壳伪装成已接真”问题

## 7. 输出要求

执行浏览器验收后，结果需回填：

- 通过项
- 失败项
- 阻塞项
- 具体页面与现象
- 是否影响 `A7-3 / A7-4` 结项
