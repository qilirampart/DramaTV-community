# 本地手动启动操作指南

日期：`2026-05-21`

适用场景：

- 电脑重启后
- 需要自己恢复本地开发环境
- 需要同时看社区前台、后台和云镜像

## 1. 端口

- 后端：`18080`
- 社区前台：`3106`
- 社区后台：`3206`
- 云镜像前台：`3107`
- PostgreSQL：`5432`
- Redis：`6379`

## 2. 标准顺序

1. 打开 Docker Desktop。
2. 启动数据库和 Redis。
3. 启动后端。
4. 启动社区前台。
5. 启动社区后台。
6. 需要看云镜像时，再启动 `3107`。

## 3. 启动命令

### 3.1 数据库和 Redis

```powershell
docker compose -f infra/local/docker-compose.yml --env-file infra/local/.env up -d
```

### 3.2 后端

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-server-18080.ps1
```

### 3.3 社区前台

```powershell
npm run dev:web
```

### 3.4 社区后台

```powershell
npm run dev:admin
```

### 3.5 云镜像前台

```powershell
npm run start:web:cloud
```

## 4. 启动后检查

1. `http://127.0.0.1:18080/actuator/health`
2. `http://127.0.0.1:3106/`
3. `http://127.0.0.1:3206/login`
4. `http://localhost:3107/`

## 5. 最小验收

1. `npm run readiness:local`
2. `npm run smoke:web`
3. `npm run smoke:admin`

## 6. 常见偏移

1. `npm run dev:web` 跑到 `3000/3001`：
   - 先停掉旧的 `node` 进程
   - 再重新启动
2. 后端起不来：
   - 先查 Docker 容器是否健康
   - 再看 `server-18080.out.log` 和 `server-18080.err.log`
3. 后台起不来：
   - 先确认后端 `18080` 已经起来
   - 再看 `3206` 是否被别的进程占用
4. 云镜像打不开：
   - 先确认你看的不是本地 `3106`
   - 云镜像只对应 `3107`
