# 测试环境部署后验收清单

日期：`2026-05-18`

适用范围：

- 测试环境前台
- 测试环境后端
- 社区前台公网入口：`http://community.8.141.20.130.nip.io`
- 管理后台公网入口：`http://community.8.141.20.130.nip.io/admin`
- 机器原始公网 IP：`http://8.141.20.130`（仅用于机器级连通性探测）

## 1. 先跑自动检查

部署后第一步：

```powershell
npm run deploy:verify:post:test
```

当前等价于：

```powershell
npm run readiness:test
```

结果会落到：

- `artifacts/runtime-readiness/test/*.json`

## 2. 先看基础可用性

至少确认：

- 根页可打开
- 登录页可打开
- `/home`
- `/featured`
- `/discussions`

如果是受保护页，匿名访问时至少要表现正确，不应黑屏或死循环。

## 3. 后端健康检查

如果当前环境可直连后端，再确认：

- `/actuator/health`
- `/api/feed/home`
- `/api/prompts?modality=all&limit=1`
- `/api/discussions/home`

## 4. 关键写链路抽查

如果这轮改动涉及发布、互动或治理，至少人工抽查一条真实链路：

- 登录
- 发布
- 点赞
- 收藏
- 评论
- 举报

不要求每次全量手测，但要覆盖这轮改动真实影响到的路径。

## 5. 浏览器级最小回归

建议至少抽查下面页面：

- 首页
- 精选页
- 讨论区
- 一个详情页
- 一个个人页

重点看：

- 是否还在跳错路由
- 是否还在黑屏 loading
- 返回列表是否回到原位置
- 媒体封面 / 视频是否异常

## 6. 如果自动检查失败

先不要直接判定是代码坏了。

按顺序区分：

1. 当前机器到公网入口不稳定
2. Nginx / 服务异常
3. 前台服务正常但后端异常
4. 后端服务正常但数据库 / Redis / OSS 异常

具体排查入口见：

- `docs/04_实施设计/测试环境部署回滚与故障排查清单-2026-05-18.md`
- `docs/04_实施设计/故障排查入口速查表-2026-05-18.md`

## 7. 部署后通过标准

至少满足下面 4 条：

1. `deploy:verify:post:test` 无明确代码级失败
2. 关键公开页可打开
3. 关键 API 可用
4. 本轮改动影响到的主路径人工抽查通过

## 8. 回滚入口

如果部署后确认需要回退，先查 release：

```powershell
npm run release:list:test
```

再按对象回退：

```powershell
npm run rollback:test:web -- -ReleaseName <release> -VerifyAfterRollback
npm run rollback:test:backend -- -ReleaseName <release> -VerifyAfterRollback
```

当前第一版稳定基线记录在：

- `ops/releases/test-env-release-ledger.md`
