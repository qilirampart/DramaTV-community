# 社区公网入口问题说明与运维支持申请

创建日期：`2026-06-11`
适用对象：公司运维 / 云资源负责人 / 域名与备案经办人
适用环境：共享测试 ECS `8.141.20.130`

## 1. 文档目的

这份文档用于收口当前 DramaTV 社区测试环境的公网访问问题，明确：

- 我们遇到了什么问题
- 目前已经确认到什么程度
- 当前可行的解决办法是什么
- 需要运维或域名/备案侧提供哪些支持

避免后续讨论时把“应用故障”“Nginx 分流”“备案拦截”“裸 IP 兜底”“临时测试口子”混在一起。

## 2. 我们遇到的情况

当前共享测试 ECS 上同时承载 `3` 个项目：

- DramaTV 社区
- DramaLoom
- 法务相似度项目

这三个项目原本都依赖同一个公网 IP `8.141.20.130`，并通过 `Nginx server_name` 在 `:80` 端口做 Host 分流。

社区原来的公网访问入口是：

- 前台：`http://community.8.141.20.130.nip.io`
- 后台：`http://community.8.141.20.130.nip.io/admin`

现在遇到的问题是：

1. `community.8.141.20.130.nip.io` 无法正常访问，浏览器会直接命中阿里云“域名暂时无法访问 / 当前备案状态不符合访问要求”的页面。
2. 我们尝试把个人域名 `skpy.ltd` 挂到社区项目上，公网访问时也会命中同类拦截页。
3. 裸 IP `http://8.141.20.130` 仍然可以访问，但当前会落到同机的 `DramaLoom` 项目，不能再作为社区的稳定公网入口。

## 3. 当前已经确认的事实

### 3.1 不是社区应用本身挂了

已经确认：

- 社区前台、后台、后端服务都在运行
- ECS 机器内部带 Host 访问社区登录页时返回 `200`
- 说明社区应用和社区 Nginx 配置本身是正常的

这意味着：

- 当前问题不是前端代码异常
- 不是后端服务异常
- 不是社区项目本身“已经挂了”

### 3.2 当前问题发生在公网入口层

从现象看，当前问题发生在应用之前的公网入口层：

- 社区原 `nip.io` 入口被阿里云备案 / 接入校验拦截
- 新挂载的 `skpy.ltd` 也被同类校验拦截

因此当前不是“一个域名坏了”，而是：

- 任何指向这台阿里云中国大陆 ECS、但又不满足当前备案 / 接入备案要求的公网域名，都可能被同样拦截

### 3.3 裸 IP 不是社区可继续使用的正式入口

当前 `http://8.141.20.130` 还能访问，只能说明：

- 这台机器公网还活着
- 当前 `:80` 默认站点还活着

但不能说明：

- 社区项目还能正常对外访问

原因是：

- 裸 IP 请求不会命中社区专属 `server_name`
- 当前裸 IP 已经落到同机的 `DramaLoom` 作为默认站点
- 因此裸 IP 不能再作为社区项目的正式公网入口继续使用

## 4. 当前我们的状况

从测试角度看，我们当前的状态是：

- 社区应用正常
- 社区 Host 分流逻辑正常
- 社区原有公网域名入口失效
- 社区新尝试的个人域名入口也失效
- 社区当前缺少一个稳定、可公网访问、且不影响同机其他项目的正式入口

换句话说：

- 当前不是服务器资源不够
- 也不是共享 ECS 不能承载多个项目
- 真正缺的是“社区项目自己的可用公网入口”

## 5. 当前可行的解决办法

### 5.1 短期恢复测试

短期内，为了不影响同机其他项目，我们已经为社区准备了临时高位端口方案：

- 社区前台：`http://8.141.20.130:8086/login`
- 社区后台：`http://8.141.20.130:8206/admin/login`

目前已确认：

- 机器内 Nginx 临时端口配置已准备
- 机器内 `firewalld` 已为 `8086/tcp`、`8206/tcp` 放行

这个方案的价值是：

- 不需要动同事当前 `:80` 默认站点
- 不需要改现有三个项目的 Host 分流关系
- 可以先恢复社区项目继续联调和测试

### 5.2 中长期恢复正式公网访问

如果要恢复社区项目的标准公网访问，建议走正式方案：

1. 为社区项目分配一个正式可用域名
2. 该域名可以在当前阿里云中国大陆 ECS 上完成备案或接入备案
3. 运维将该域名挂到社区项目自己的 `server_name`
4. 社区、DramaLoom、法务项目继续共用 `:80`，但通过不同域名做 Host 分流

这才是共享 ECS 多项目长期稳定共存的正路。

## 6. 我们当前需要的支持

### 6.1 需要运维支持的事项

请协助确认：

1. 当前这台共享 ECS 的裸 IP `http://8.141.20.130` 是否已经作为其他项目默认站点入口固定使用
2. 社区项目是否可以先临时开放以下测试端口：
   - `TCP 8086`
   - `TCP 8206`
3. 阿里云控制台的 ECS 安全组入站规则是否已放行上述两个端口

### 6.2 需要域名 / 备案经办侧支持的事项

请协助确认：

1. 是否能为社区项目分配一个正式可用域名
2. 该域名是否已备案
3. 如果已备案，是否可以在当前阿里云实例上做接入备案
4. 如果未备案，是否准备新增备案并挂载到社区项目

## 7. 我们建议的处理顺序

建议按下面顺序推进：

1. 先由运维确认并放行 `8086/8206`，恢复社区项目短期测试入口
2. 并行确认社区正式域名方案
3. 域名确认后，推进备案或接入备案
4. 域名合规后，再把社区正式公网入口切回 `:80 + 独立域名`

## 8. 一句话总结

当前 DramaTV 社区的问题不是应用挂了，也不是服务器不够，而是：

> 共享 ECS 上社区原有域名入口和新尝试域名入口都被阿里云备案 / 接入校验拦截，裸 IP 又只能落到同机默认站点，因此社区当前缺少自己的稳定公网入口。短期建议先放行 `8086/8206` 恢复测试，长期需要为社区分配可备案 / 可接入备案的正式域名。
