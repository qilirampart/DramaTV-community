# 最小 CI 草案

日期：`2026-05-18`

## 1. 目标

这一版不是完整上线流水线，只先解决最小问题：

- 每次提交或提 PR 时，自动跑前台质量门禁
- 自动跑后台前端质量门禁
- 自动跑后端关键集成测试

当前草案不处理：

- 自动部署
- 浏览器级 E2E
- 公网环境验收
- 一键回滚

## 2. 当前落地结果

仓库已新增：

- `.github/workflows/ci-minimal.yml`

当前 CI 拆成 3 个 job：

1. `web-quality`
2. `admin-quality`
3. `backend-core`

## 3. 各 job 负责什么

### 3.1 `web-quality`

负责：

- 安装 `apps/web` 依赖
- 运行 `npm run typecheck:web`
- 运行 `npm run build:web`

### 3.2 `admin-quality`

负责：

- 安装 `apps/admin` 依赖
- 运行 `npm run typecheck:admin`
- 运行 `npm run build:admin`

### 3.3 `backend-core`

负责：

- 拉起临时 `PostgreSQL 16`
- 拉起临时 `Redis 7`
- 使用 `Java 17 + Maven`
- 跑后端关键集成测试：
  - `AuthMeApiIntegrationTest`
  - `DraftApiIntegrationTest`
  - `InteractionApiIntegrationTest`
  - `CommentApiIntegrationTest`
  - `PublishBootstrapApiIntegrationTest`
  - `PublishPipelineIntegrationTest`

## 4. 为什么这版先不直接复用根脚本

根目录的统一脚本适合本机开发，但当前后端分组脚本依赖：

- Windows PowerShell
- 本地 `.tools` 里的 Java / Maven

CI runner 是 `ubuntu-latest`，所以这版在工作流里直接写：

- `npm ci`
- `npm run typecheck:*`
- `npm run build:*`
- `mvn -f apps/server/pom.xml ... test`

这样更直接，也不会把本机路径假设带进 CI。

## 5. 这版 CI 的边界

当前这版更像“最小质量门禁”，不是完整发布系统。

已经覆盖：

- 前端基础静态检查
- 前端构建
- 后端关键集成测试

暂未覆盖：

- 浏览器 smoke
- 管理后台真实接口 smoke
- 测试环境 readiness
- 部署脚本自检
- OSS / 媒体代理链路专项检查

## 6. 下一步可继续补什么

下一轮如果继续补 CI，优先顺序建议是：

1. 增加 `backend-test:read`
2. 增加 `backend-test:admin`
3. 增加浏览器级 smoke 的可执行环境
4. 增加部署前后的自动验收分层
