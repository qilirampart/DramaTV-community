# 故障排查入口速查表

日期：`2026-05-18`

这份表只解决一个问题：

- 出问题时先去哪里查，不要先盲猜

配套长文档见：

- `docs/04_实施设计/测试环境部署回滚与故障排查清单-2026-05-18.md`

## 1. 本地服务起不来

先按这个顺序查：

1. Docker 是否已启动
2. PostgreSQL / Redis 容器是否在运行
3. 后端端口是否被占用
4. Java 17 / Maven 是否可用
5. `npm run readiness:local` 是否报出明确失败点

常用入口：

- `docker compose -f infra/local/docker-compose.yml --env-file infra/local/.env ps`
- `powershell -ExecutionPolicy Bypass -File scripts/run-server-local-db.ps1`
- `npm run readiness:local`

## 2. 前后端看起来不同步

先查：

1. 你看的到底是 `3106`、`3107` 还是公网
2. 这轮改动是否只在本地前端生效
3. 是否实际没有同步云后端或公网前端
4. 浏览器是否还带旧缓存 / 旧登录态

当前常见口径：

- `3106`：本地主前台
- `3107`：本机云镜像前端
- `8.141.20.130`：测试环境公网入口

## 3. 公网打不开或异常

先按这个顺序查：

1. 本机到 `8.141.20.130:80` 是否可达
2. `http://8.141.20.130/` 是否 `200`
3. Nginx 是否正常
4. 前台服务是否 `active (running)`
5. 后端健康检查是否通过

不要把“当前网络不可达”误判成“代码刚部署坏了”。

## 4. 页面能开但接口不对

先查：

1. `/api/feed/home`
2. `/api/prompts`
3. `/api/discussions/home`
4. `/actuator/health`

如果前台 HTML 正常但接口异常，优先怀疑：

- 后端服务异常
- 数据库 / Redis / OSS 连通异常
- 代理层转发异常

## 5. 后台改动误伤前台

先查：

1. 是否改到了共享接口
2. 是否改到了共享 DTO / mapper / query service
3. 是否只跑了后台页面，没有补前台 smoke
4. 是否需要补跑共享层回归

当前共享高风险区：

- 登录 / 会话
- 评论
- 通知
- 举报
- 发布与草稿

## 6. 部署失败或部署后异常

先查：

1. `npm run deploy:verify:pre` 是否之前已通过
2. 部署脚本卡在本地打包、上传、远端构建、重启还是健康检查
3. 当前 `current` release 指向哪个版本
4. 是否需要先回滚到上一个已知正常 release

## 7. 最短思路

排查顺序固定为：

1. 先分清环境
2. 再分清是前台、后端还是网络
3. 先看健康点
4. 再看日志
5. 最后再动回滚
