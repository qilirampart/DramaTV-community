# 后端本地数据库启动与建表验证

更新日期：2026-04-07

## 1. 这份文档解决什么问题

这份文档只解决一件事：

- 把 `apps/server` 用本地 `PostgreSQL + Redis` 真正启动起来
- 让 `Flyway` 自动执行迁移并创建业务表
- 给后续“发布草稿落库、评论落库、工作流复制任务落库”打基础

## 2. 当前启动模式

后端当前统一按全链路模式启动：

- 默认模式：`local-db`
- 连接 `PostgreSQL + Redis`
- 启动时执行 `Flyway` 建表

规则：

- 不显式传 profile 时，默认走 `local-db`
- 当前不再以 `mock` 作为日常开发或验收入口
- 当前仓库已移除 `mock` profile 配置，后端默认只保留真实数据库启动路径

## 3. 启动前提

需要先确认下面 3 件事：

1. 本地容器已经启动
2. `dramatv-postgres` 和 `dramatv-redis` 处于运行状态
3. 本地 Java / Maven 工具链已经准备好

可用命令：

```powershell
docker compose -f infra/local/docker-compose.yml --env-file infra/local/.env ps
```

```powershell
powershell -ExecutionPolicy Bypass -File scripts/use-local-java17-maven.ps1
```

## 4. 推荐启动命令

统一使用下面这个脚本：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/run-server-local-db.ps1
```

这个脚本会自动做两件事：

- 读取 `apps/server/.env.example` 和可选的 `apps/server/.env`
- 用本地 `Java 17 + Maven` 以 `local-db` profile 启动 `Spring Boot`

如果后面你新增了 `apps/server/.env`，它会覆盖示例配置。

### 4.1 当 `8080` 被占用时的临时验证方式

本机如果同时开着旧前端原型、Vite 服务或其他本地服务，`8080` 很容易被占用。

这时不要把问题先归因到数据库或 Flyway，先换一个临时端口做验证更高效。

在已经完成后端构建后，可以直接用打包产物临时起服务：

```powershell
E:\点众\DramaTV社区搭建\.tools\jdk-17\bin\java.exe `
  -Dspring.profiles.active=local-db `
  -Dserver.port=18080 `
  -jar E:\点众\DramaTV社区搭建\apps\server\target\dramatv-community-server-0.1.0-SNAPSHOT.jar
```

这条命令适合做两类事情：

- 快速验证 `publish_drafts` 等真实落库链路是否可用
- 在 `8080` 被占用时继续完成数据库建表、接口联调和 pgAdmin 对照检查

## 5. 启动成功后应该看到什么

启动成功后，日志里应该至少出现这类结果：

- `Flyway` 开始执行 `V1 / V2 / V3`
- `Started DramaTvCommunityServerApplication`
- 服务监听 `8080`

然后数据库里应该出现这些核心表：

- `users`
- `creator_profiles`
- `media_assets`
- `workflows`
- `videos`
- `feed_items`
- `publish_drafts`
- `comments`
- `interaction_actions`
- `follow_relations`
- `canvas_bindings`
- `canvas_workflow_runtimes`
- `canvas_runtime_assets`
- `canvas_copy_tasks`
- `async_task_records`
- `task_callback_logs`

## 6. 验证命令

如果想直接在命令行验证建表结果，可以执行：

```powershell
docker compose -f infra/local/docker-compose.yml --env-file infra/local/.env exec postgres `
  psql -U dramatv -d dramatv -c "\dt"
```

如果想图形化验证，就继续使用 `pgAdmin` 查看：

- `DramaTV Local PG`
- `dramatv`
- `schemas -> public -> tables`

## 7. 当前意义

这一步完成后，项目状态会从：

- “本地环境已具备数据库和缓存”

推进到：

- “后端默认按真实链路启动，并自动初始化表结构”

这会直接打开下一步：

1. 先把 `publish_drafts` 接成真实落库
2. 再把评论、互动、作者页统计逐步接入持久化
3. 最后再推进工作流复制任务和异步任务落库
