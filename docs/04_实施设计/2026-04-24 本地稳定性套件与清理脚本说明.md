# 2026-04-24 本地稳定性套件与清理脚本说明

## 1. 目标

给 DramaTV 社区项目补一套可复跑、可沉淀结果的本地稳定性入口，避免后续每次都手敲多条命令。

本轮新增两类能力：

- 一键本地稳定性套件
- 本地过期脏数据清理预览 / 应用

## 2. 新增入口

### 2.1 一键稳定性套件

默认稳定入口：

```powershell
npm.cmd run stability:local
```

默认执行内容：

- 后端健康检查
- 前端首页可达检查
- 前端 `TypeScript` 检查
- 后端 HTTP 级集成测试
- API smoke

默认不包含：

- 前端生产构建
- Browser smoke

原因：

- 这两项在当前本地 Windows / Playwright / Next.js 环境下更容易受工具链和权限影响
- 默认入口优先保证“日常开发可稳定复跑”
- 更重的检查仍保留单独入口

增强入口：

```powershell
npm.cmd run stability:local:full
```

### 2.2 独立 smoke 入口

```powershell
npm.cmd run smoke:api
npm.cmd run smoke:browser
```

### 2.3 启动后验活 / 关键依赖自检

后端 + 前端联合自检：

```powershell
npm.cmd run readiness:local
```

只检查后端和依赖：

```powershell
npm.cmd run readiness:local:backend
```

当前自检覆盖：

- 后端 `/actuator/health`
- PostgreSQL `127.0.0.1:5432` TCP
- Redis `127.0.0.1:6379` TCP
- 核心公共 API：`/api/feed/home`、`/api/prompts`、`/api/discussions/home`
- 登录链路：`/api/auth/login`、`/api/auth/me`、`/api/me/hub`
- 前台根页 `/`
- 游客访问 `/home` 的登录重定向
- 带登录 cookie 访问 `/me`

同时，启动脚本已默认接入这层后验活：

- `scripts/start-server-dev-18080.ps1`
- `scripts/start-web-3100.ps1`

如果只想启动、不跑后验活，可以显式传 `-SkipReadinessCheck`。

补充说明：

- 如果本机已经跑着 `next dev`（例如 `3106`），再用备用端口起第二个 `dev` 进程时，Next.js 会直接拒绝并提示“Another next dev server is already running”
- 因此前端启动脚本的备用端口验活，更适合用 `-Mode start` 做验证；这次 `3107` 的真实启动与 readiness 已按这个方式跑通
