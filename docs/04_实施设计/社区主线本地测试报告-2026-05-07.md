# DramaTV 社区主线本地测试报告

更新日期：2026-05-07

## 1. 测试概览

- 测试目标：基于当前正式主线 `apps/web + apps/server`，验证 DramaTV 社区本地环境的核心闭环是否仍然可用。
- 测试环境：
  - 前端：`http://127.0.0.1:3106`
  - 后端：`http://127.0.0.1:18080`
  - 数据库：本地 PostgreSQL `127.0.0.1:5432`
  - Redis：本地 Redis `127.0.0.1:6379`
- 测试账号：
  - 主账号：`creator-a / dramatv-local-dev`
  - 自动化临时账号：脚本运行时自动创建 `qa-smoke-*`
- 测试方式：
  - 自动化运行时就绪检查
  - 自动化社区 API smoke
  - 自动化登录 / 会话 / 权限回归
  - Playwright 浏览器级人工复检

## 4. 浏览器级复检结果

本轮使用 Playwright 对 `http://127.0.0.1:3106` 做了可见页面复检。

### 已确认通过

- 匿名态访问 `/` 时，首页可浏览，但“画布入口 / 发布入口”都会先跳登录。
- 从匿名态点击“进入画布入口”，会正确到 `/login?redirectTo=%2Fcanvas`。
- 使用 `creator-a / dramatv-local-dev` 登录后，会正确跳转到画布占位页。
- 画布占位页“返回社区”可回到 `/home`。
- 首页顶部导航 `/home -> /featured -> /discussions` 可正常跳转。
- 首页通知面板可以正常打开。
- 首页资源卡进入提示词详情页后，`返回列表` 会按 `from + hash` 回到原位置。
- 讨论区列表可以进入帖子详情页。
- 帖子详情页主体结构、右侧信息列、作者跳转位均能正常展示。
- 本轮浏览器会话控制台错误：`0`

## 5. 本轮发现的问题

### F1. 讨论区左侧频道仍混入测试残留栏目

- 页面：`/discussions`
- 现象：左侧频道列表中除了正式中文栏目外，还出现了两个英文 `Integration Channel`
- 判断：更像测试数据或中间态频道未清理，不像代码功能错误
- 影响：
  - 会污染正式社区栏目观感
  - 容易让后续测试人员误判这是正式频道设计
- 建议优先级：`P1`
- 建议处理：
  - 先确认这两个频道是否仅用于集成测试
  - 若是测试残留，清理正式环境/本地演示环境中的频道数据
  - 若需要保留测试频道，至少不要出现在前台正式栏目列表

## 6. 风险与缺口

- 当前自动化主要覆盖“接口与基础状态正确”，但还没有覆盖“真实浏览器发布视频后等待媒体处理完成”的整条用户体验链路。
- 当前没有做一轮公网环境对照回归，因此本地通过不等于云环境完全同步无差异。
- 评论通知本轮只验证了会话与面板可打开，没有重新执行“多账号互评触发通知”的浏览器级复检。
- 本轮没有做性能 trace，因此像“多次进入退出详情页后的卡顿”这类体感问题，本报告不能作为性能无问题的证明。

## 7. 测试结论

- 结论：当前本地社区主线可判定为“核心闭环可用”。
- 已验证通过的核心闭环包括：
  - 匿名访问边界
  - 登录与会话
  - 首页 / 精选 / 社区主导航
  - 详情页进入与返回
  - 草稿基础写链路
  - 上传策略
  - 点赞 / 收藏 / 关注
  - 评论治理基础链路
- 当前阻塞上线演示的明确问题，本轮只发现 1 项数据清理类问题：讨论区测试频道残留。

## 8. 建议的下一步测试顺序

1. 先清理讨论区测试频道残留，避免正式演示环境混入测试数据。
2. 做一轮浏览器级工作流发布链路测试：
   - 发工作流
   - 继续复检图片提示词 / 视频提示词的稳定性
3. 做一轮公网 `8.141.20.130` 对照回归，确认云端与本地主线一致。
4. 单独开性能专项，复检：
   - 高频切换分类
   - 多次进入退出详情页
   - 首页与精选视频卡片加载策略
