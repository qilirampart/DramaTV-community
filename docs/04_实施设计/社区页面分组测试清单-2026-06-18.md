## 1. 用法

这份清单不是完整测试报告，也不是一次性用例库。

它的定位是：

1. 每次改动后快速确认受影响页面。
2. 每次上云前做一轮最小但有效的回归。
3. 每次发现共享问题后，能立刻知道相邻页面还要补扫哪些点。

建议执行顺序：

1. 先跑 `登录 / 会话`
2. 再跑 `精选 / 作者页 / 社区`
3. 再跑 `首页 / 个人中心 / 发布页`
4. 最后补 `详情页族` 和 `跨页多跳链路`

## 2. 记录方式

每次执行时，建议只记录 3 类结果：

- `通过`
- `失败`
- `需观察`

如果失败，至少补：

- 路由
- 操作步骤
- 实际结果
- 预期结果
- 是否只在云端复现

建议至少跑：

- 登录与会话全组
- 精选页全组
- 社区页全组
- 作者页全组

- 视觉与可读性专项

## 14. 当前固定高风险提醒

对这个项目，下面 5 类问题后续每轮都不要漏：

1. `/featured` 深滚动后返回定位
2. `/featured` 返回后继续加载
3. `/creators/[id]` 首次返回是否生效
4. `/discussions` 帖子详情返回列表
5. 云端真实数据下的分类/搜索/资源类型语义
