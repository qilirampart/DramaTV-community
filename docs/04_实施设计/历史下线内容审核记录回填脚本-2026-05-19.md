# 历史下线内容审核记录回填脚本

日期：`2026-05-19`

## 背景

在 `2026-05-19` 的 `/reports -> /moderation -> restore` 联动复核里，确认了一类历史残留：

- 某些内容已经是 `publish_status = taken_down`
- 但没有对应的 `audit_records.publish_review`
- 结果是后台 `/moderation` 看不到这类内容，无法执行 `restore`

主链修复后，这个问题对“修复后再次触发的 `offline-target`”已经成立。

但主链修复不会自动回填历史旧数据，所以补了一次性修复脚本。

## 脚本位置

- `scripts/backfill-historical-moderation-audits.mjs`

## 修复范围

当前脚本只处理：

- 内容当前 `publish_status = taken_down`
- 且缺少 `audit_type = publish_review` 的审核记录

覆盖目标类型：

- `video`
- `workflow`
- `prompt`
- `post`

## 使用方式

先预览，不直接写库：

```bash
npm run moderation:backfill:preview
```

确认后执行写入：

```bash
npm run moderation:backfill:apply
```

也可以定向修复单条内容：

```bash
node scripts/backfill-historical-moderation-audits.mjs --target-type prompt --target-id <uuid>
node scripts/backfill-historical-moderation-audits.mjs --apply --target-type prompt --target-id <uuid>
```

显式指定本地库：

```bash
node scripts/backfill-historical-moderation-audits.mjs --target local
node scripts/backfill-historical-moderation-audits.mjs --target local --apply
```

针对测试/云库预览或执行：

```bash
node scripts/backfill-historical-moderation-audits.mjs --target remote
node scripts/backfill-historical-moderation-audits.mjs --target remote --apply
```

如果需要显式指定测试环境资源文件：

```bash
node scripts/backfill-historical-moderation-audits.mjs --target remote --resource-file .codex/测试环境资源清单.md
```

如果 SSH 隧道已经单独起好，也可以跳过自动起隧道：

```bash
node scripts/backfill-historical-moderation-audits.mjs --target remote --skip-tunnel --local-port 15432
```

## 产物

每次执行都会落地：

- `artifacts/moderation-backfill/latest/summary.json`

产物里会记录：

- 目标库：`local / remote`
- 是否是 dry-run / apply
- 命中的候选内容
- 实际写入数量
- 写入后剩余未修复数量

## 写入策略

脚本会为命中的历史内容补一条 `audit_records`：

- `audit_type = publish_review`
- `status_code = taken_down`
- `risk_level = high`
- `reason_code = historical_backfill`
- `operator_type = system`
- `operator_id = null`

并在 `detail_json` 里补：

- `repairSource`
- `repairReason`
- `repairedAt`
- `backfilledPublishStatus`
- `backfilledAuditCreatedAt`

`created_at` 不取当前时间，而是尽量沿用内容自身时间：

- `coalesce(updated_at, published_at, created_at, now())`

这样可以避免把历史修复误记成“今天新处理的审核内容”。

## 注意事项

- 这个脚本不会修改内容本身的 `publish_status`
- 只补缺失的审核记录
- 脚本是幂等的；同一条内容回填成功后，再次执行不会重复插入
- 如果某条旧内容已经被手工恢复，当前脚本也不会再命中它
- `--target remote` 当前复用现有测试环境 SSH tunnel + Docker `psql` 口径：
  - 资源文件默认自动从 `.codex/*.md` 中识别
  - 默认隧道本地端口：`15432`
  - 默认 Docker 容器名：`dramatv-postgres`
