## 1. 任务背景

这轮不是单点前台小修，而是近期社区前台、管理后台、共享后端的一次合并同步。

当前已确认的风险特征:

- `web` 部署会重写社区站点 Nginx 配置，必须继续锁定社区专属 Host，不能回到裸 IP 或 catch-all。
- `backend` 本轮包含共享读口径、管理后台支撑能力与数据库迁移，代码回滚和数据回滚必须分开考虑。
- `admin` 依赖新后端接口与新前台展示语义，不能只发一边。
- 当前工作区为 dirty workspace，发布前必须先补备份与回滚锚点，不能直接按“本地当前状态”裸发。

## 2. 本轮同步范围判断

### 2.1 必发

- `apps/web`
  - 首页拼贴与 hero 调整
  - `/featured` 瀑布流、滚动分页、返回定位、默认排序、性能收口
  - 登录页清理与画布外链入口
  - 社区页/作者页/详情页若干展示统一

- `apps/admin`
  - `feed-ops/featured` 最新/最热分配置
  - `feed-ops/landing`
  - taxonomy 治理页与资源治理口径补齐
  - 后台登录页与若干管理页修正

- `apps/server`
  - `featured-inventory` 与精选库存分页口径
  - feed-ops / taxonomy / creator / media / auth 相关共享后端修复
  - Flyway 迁移 `V24` ~ `V27`

### 2.2 关键依赖

- Nginx:
  - `/` -> community web
  - `/api/` `/media/` -> community backend
  - `/admin` -> community admin
- 数据库:
  - `admin_feed_slot_configs`
  - `admin_taxonomy_configs`
- 发布台账:
  - `ops/releases/test-env-release-ledger.md`

## 3. 发布原则

1. 先备份，再发布。
2. 先后端，再后台，再前台。
3. 每段发布后立刻做该段最小可用性验证，不等三端全发完再统一排障。
4. 公网业务入口统一以 `community.8.141.20.130.nip.io` 为准，裸 IP 只用于机器探活。
5. 如果某一段验证失败，先停在当前段，不继续向下一段扩散。

## 5. 回滚原则

### 5.1 Web

- 优先回滚到上一条已知正常 `web release`
- 如涉及入口异常，同时恢复 Nginx 备份

### 5.2 Admin

- 优先回滚到上一条已知正常 `admin release`
- 保持 `/admin` basePath 与前台 Host 不变

### 5.3 Backend

- 优先回滚到上一条已知正常 `server release`
- 如果问题落在迁移后的配置数据，优先恢复定向 SQL 备份
- 整库回滚只作为最后手段

## 6. 本轮暂停条件

出现以下任一情况，暂停继续向下发布:

- 后端迁移执行后 `/actuator/health` 或核心读取接口异常
- `/admin` 已无法进入或 featured/taxonomy 配置读写明显异常
- 社区专属 Host 再次指向同机其他项目
- 发布后前台首页、精选页或登录页出现不可用主故障
- 回滚锚点记录不完整

## 7. 完成记录规则

- 每完成一个任务，立刻更新本任务板状态。
- 每个阶段至少记录:
  - 做了什么
  - 验证证据
  - 当前回滚锚点
  - 是否继续下一阶段
