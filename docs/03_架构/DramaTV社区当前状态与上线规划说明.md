# DramaTV 社区当前状态与上线规划说明

更新时间：2026-04-20

配套图：

- `docs/03_架构/DramaTV社区功能脑图-详细版.drawio`
- `docs/03_架构/DramaTV社区关键联动链路图.drawio`

## 1. 当前结论

DramaTV 社区现在已经从纯页面复刻推进到“本地真实前后端闭环”阶段。

当前已经具备：

- 正式前端：`apps/web`，Next.js + React + TypeScript。
- 正式后端：`apps/server`，Spring Boot。
- 本地基础设施：PostgreSQL + Redis。
- 真实接口链路：前端通过 `DRAMATV_API_BASE_URL=http://127.0.0.1:18080` 访问后端。
- 真实数据库写入：登录、发布、评论、点赞、收藏、关注、讨论、媒体资产 metadata 都已经进库。
- PGC 内容池：已经导入 YouMind 图片提示词、视频提示词和部分本地可播放视频资产。

目前最重要的判断：

页面层已经基本成型，下一阶段重点不应继续堆页面，而是补齐上线需要的基础设施、审核后台、云存储、真实画布对接和运维体系。

## 2. 已完成能力

### 2.1 页面与用户路径

当前正式页面范围：

- `/`
- `/home`
- `/featured`
- `/discussions`
- `/discussions/new`
- `/discussions/[slug]`
- `/publish`
- `/videos/[id]`
- `/workflows/[id]`
- `/prompts/[id]`
- `/creators/[id]`
- `/me`
- `/login`
- `/canvas`
- `/canvas/[runtimeId]`

已完成的主路径：

- 游客可以浏览首页。
- 游客点击受限操作时触发登录。
- 登录后可访问发布页、讨论发帖页、个人中心、画布入口。
- 首页、精选、详情页、讨论页、作者页已经统一走真实后端数据。
- 发布帖子后可进入帖子详情，并可在讨论广场看到。
- 发布视频后可进入视频详情。
- 点赞、收藏、关注、评论已不再是纯假数据，已接后端写入。

### 2.2 后端模块

后端已覆盖：

- `identity-auth`：登录、登出、当前用户、会话。
- `feed-discovery`：首页聚合。
- `video-content`：视频详情、相关视频。
- `workflow-content`：工作流详情、关联视频。
- `prompt-content`：提示词列表、提示词详情、相关提示词。
- `creator-profile`：作者主页、作者作品和工作流聚合。
- `discussion`：讨论广场、帖子详情。
- `publish`：视频草稿、工作流草稿、帖子草稿、上传策略、提交发布。
- `interaction-comment`：点赞、收藏、关注、评论。
- `canvas-link`：画布入口、复制到画布占位、runtime 快照。
- `internal-callback`：媒体、工作流校验、审核回调接口位。

### 2.3 数据库实体

当前已建表覆盖：

- 用户与作者：`users`、`auth_sessions`、`creator_profiles`
- 内容：`videos`、`workflows`、`prompt_entries`
- 媒体：`media_assets`、`prompt_example_links`
- 分发：`feed_items`
- 发布：`publish_drafts`
- 审核与举报：`audit_records`、`report_tickets`
- 讨论：`discussion_channels`、`discussion_threads`
- 互动：`comments`、`interaction_actions`、`follow_relations`
- 画布：`canvas_bindings`、`canvas_workflow_runtimes`、`canvas_runtime_assets`、`canvas_copy_tasks`
- 异步任务：`async_task_records`、`task_callback_logs`

## 3. 当前本地数据和云端迁移判断

### 3.1 当前本地数据

当前本地内容主要来自：

- YouMind 图片提示词数据。
- YouMind 视频提示词数据。
- `docs/02_研究/youmind-video-assets` 下的本地可播放视频资产。
- 本地种子工作流和演示工作流数据。
- 本地用户、评论、点赞、收藏、关注、帖子发布数据。

### 3.2 上线必须迁移到云的内容

必须迁移到对象存储或云存储：

- 视频源文件。
- 视频预览文件。
- 视频封面、poster、cover。
- 图片提示词示例图。
- 用户后续上传的图片、视频、附件。
- 画布 runtime 中可见的图片、视频、预览资产。

推荐形态：

- 对象存储：OSS / S3 / MinIO。
- 分发：CDN。
- 数据库存储：只保存 `storage_provider`、`bucket_name`、`object_key`、`mime_type`、`size_bytes`、`duration_ms` 等 metadata。

### 3.3 继续放数据库的数据

适合继续放 PostgreSQL：

- 用户账号映射、画布账号映射、会话。
- 作者资料。
- 视频、工作流、提示词、帖子元数据。
- 提示词正文。
- 标签、分类、可见性、发布状态。
- 内容与媒体资产的引用关系。
- 评论、点赞、收藏、关注。
- 发布草稿。
- 审核记录和举报记录。
- 异步任务记录。
- 画布 runtime 和 copy task 的业务状态。

不建议放数据库：

- 大视频二进制。
- 大图片二进制。
- 完整原始工作流大 JSON。
- 超长第三方原始响应。

## 4. 还没有完成的关键能力

### 4.1 审核机制

当前状态：

- 表结构已经有 `audit_records`、`report_tickets`。
- 后端已经有 `POST /api/internal/audit-callback` 接口位。
- 视频和帖子当前为了本地联调，采用直接发布。
- 工作流发布仍保留 `in_review` 状态占位。

未完成：

- 没有独立后台管理系统。
- 没有审核队列页面。
- 没有运营处理举报、评论、内容上下架的界面。
- 没有敏感词、机审、人审结合流程。
- 没有 RBAC 后台权限。

建议：

审核机制归入后续后台管理系统需求，不要继续塞进社区前台页面。

### 4.2 媒体处理

当前状态：

- 本地上传写入 `tmp/media`。
- 后端最大视频策略已经支持 300MB。
- 前端上传限制已放宽到 100MB。
- 数据库能记录媒体 metadata。

未完成：

- 没有 OSS 预签名直传。
- 没有正式转码。
- 没有封面抽帧。
- 没有 preview 生成。
- 没有媒体安全扫描。
- 没有 CDN 缓存策略。
- 没有对象存储生命周期管理。

### 4.3 画布真实对接

当前状态：

- 社区有画布入口。
- 工作流详情可发起 copy-to-canvas。
- 后端可创建 `canvas_workflow_runtimes` 和 `canvas_copy_tasks` 占位。
- `/canvas/[runtimeId]` 可展示轻量快照。

未完成：

- 没有接公司画布的真实登录态。
- 没有真实工作流复制 API。
- 没有真实画布空间选择。
- 没有真实运行结果回流。
- 没有派生链路。

建议：

先对接登录，再对接工作流复制，最后再做 runtime 结果回流。

### 4.4 搜索、推荐和运营

当前状态：

- 首页和精选页可以从数据库读取内容。
- 筛选和排序主要是当前业务查询和简单排序。

未完成：

- 没有搜索引擎。
- 没有搜索索引更新任务。
- 没有运营精选配置后台。
- 没有真实热度、完播、复制率、收藏率等排序信号。
- 没有榜单和专题后台。

建议：

冷启动阶段先用运营精选 + 简单热度，内容规模上来后再接搜索引擎和推荐系统。

## 5. 距离完整上线项目的差距

### 5.1 技术基础设施

上线前需要补齐：

- 线上 PostgreSQL。
- 线上 Redis。
- 对象存储和 CDN。
- HTTPS、域名、Nginx 或网关。
- 后端容器化部署。
- 前端构建和部署流程。
- 环境变量和密钥管理。
- 数据库备份和恢复策略。

### 5.2 安全与治理

上线前需要补齐：

- 真实登录体系对接公司画布产品。
- 上传鉴权。
- 文件类型和大小策略生产化。
- 评论和帖子风控。
- 内容审核后台。
- 举报处理。
- 后台 RBAC。
- 操作审计。

### 5.3 可观测性与排障

当前已经有：

- 前端请求携带 `X-Request-Id`。
- 后端响应和日志写入 `requestId`。
- 应用日志、错误日志、访问日志分文件。

还需要：

- 线上日志采集。
- 错误告警。
- 指标监控。
- 慢接口分析。
- 上传、发布、画布复制链路的业务追踪面板。

### 5.4 产品完善

上线前建议补齐：

- 发布后的内容管理列表。
- 草稿列表、编辑、删除。
- 个人中心内容聚合。
- 作者页作品和工作流管理视角。
- 通知中心。
- 更明确的发布成功跳转和状态提示。
- 移动端关键路径回归。

## 6. 推荐推进路线

### 第一阶段：本地闭环固化

目标：

- 确认当前所有正式页面都稳定走真实后端。
- 清理内部测试页和旧页面入口。
- 固化本地 PGC 内容池。
- 明确可给老板演示的主路径。

### 第二阶段：云端内容池

目标：

- 建立线上数据库。
- 把 YouMind 图片、视频、提示词和媒体资产迁移到对象存储。
- 将媒体 `object_key` 回写数据库。
- 前台通过 CDN 或受控 URL 访问媒体。

### 第三阶段：账号和发布生产化

目标：

- 对接公司画布产品登录。
- 上传链路改为 OSS 预签名。
- 视频发布接入媒体处理队列。
- 发布状态从本地直发切换为可审核、可回滚、可追踪。

### 第四阶段：后台管理系统

目标：

- 建立审核后台。
- 建立举报处理。
- 建立内容上下架。
- 建立精选、榜单、专题运营配置。
- 建立后台 RBAC 和操作审计。

### 第五阶段：画布真实联动

目标：

- 工作流复制到真实画布空间。
- 画布运行结果回流社区。
- 建立工作流派生链。
- 社区从“展示结果和方法”升级为“发现方法、复制方法、再创作并回流”的闭环。

## 7. 给老板汇报时的一句话

现在社区已经完成了基础前后端闭环，不再只是页面 demo。下一步的核心不是继续补页面，而是把本地内容池、上传、审核、登录、媒体存储和画布联动按上线标准生产化。做到这一步后，DramaTV 社区就能从 PGC 冷启动内容展示，推进到可运营、可发布、可互动、可联动画布的正式社区产品。
