# DramaTV 社区运维与云资源对接文档

更新时间：2026-04-21

## 1. 文档目的

这份文档用于和公司运维、云资源、后端联调同事对齐 DramaTV 社区从本地环境迁移到测试环境、预发环境和线上环境时需要准备的资源、配置和确认事项。

当前项目已经不是单纯页面 Demo，而是 `Next.js 前端 + Spring Boot 后端 + PostgreSQL + Redis` 的本地真实闭环。后续要上线，需要把本地文件、数据库、缓存、日志、入口代理和媒体资源逐步迁移到公司统一基础设施上。

## 2. 当前项目状态

### 2.1 当前阶段

当前阶段为 `PGC 冷启动阶段`。

当前重点不是先做复杂推荐、交易、后台大系统，而是先把社区的内容浏览、发布、评论、点赞、收藏、作者主页、个人中心和画布入口跑通。

## 4. 线上目标架构

```text
用户浏览器
  |
  | HTTPS
  v
CDN / WAF / Nginx / 网关
  |
  |-- 前端 Next.js 服务
  |
  |-- 后端 Spring Boot API
        |
        |-- PostgreSQL：业务数据
        |-- Redis：登录态、缓存、限流短状态
        |-- Object Storage：视频、图片、封面、预览、附件
        |-- Queue：媒体处理、审核、画布复制等异步任务
        |-- Python Worker / FastAPI：转码、抽帧、预览生成、AI 任务
        |-- 日志采集 / 监控告警：应用日志、错误日志、访问日志、指标
```

### 5.1 环境与域名

| --- | --- | --- |
| 测试环境域名 | 给内部联调用，例如 `community-test.xxx.com` | 必需 |
| 预发环境域名 | 尽量贴近线上，用于上线前验收 | 建议 |
| 线上环境域名 | 正式访问入口 | 必需 |
| HTTPS 证书 | 由公司统一证书管理或云厂商证书服务提供 | 必需 |
| 内外网访问策略 | 明确哪些服务公网可访问，哪些只能内网访问 | 必需 |

确认点：

- 前端、后端是否共用一个主域名，通过路径区分，例如 `/api` 转后端。
- 是否需要单独的静态资源域名或 CDN 域名。
- 是否接入公司统一 WAF、防刷、访问控制策略。

### 5.2 计算资源

| 服务 | 最小建议 | 说明 |
| --- | --- | --- |
| 前端 Next.js | 1 个容器或 1 个进程 | 可和后端同机部署，但建议独立进程 |
| 后端 Spring Boot | 1 个容器或 1 个进程 | 需要 Java 17+ |
| Python Worker / FastAPI | 初期可暂缓，媒体处理上线前必须补 | 负责重媒体异步任务 |
| Nginx / 网关 | 公司统一入口 | 负责 HTTPS、反代、缓存头、限流 |

如果初期只分配一台小服务器，也可以先采用单机部署：

- 同机运行前端、后端、Nginx。
- PostgreSQL 和 Redis 可暂时同机 Docker 化，但不建议长期用于正式线上。
- 视频、图片等大文件不要长期放在服务器磁盘，应该尽快接对象存储。

当前数据库中主要存：

- 用户和作者资料。
- 视频、工作流、提示词、帖子元数据。
- 发布草稿。
- Feed 索引。
- 评论、点赞、收藏、关注。

不应放入数据库的大对象：

- 大图片文件。

| 需要项 | 说明 |
| --- | --- |
| 存储服务 | OSS / S3 / MinIO / 公司内部对象存储 |
| Bucket | 按环境隔离，例如 `dramatv-test-media`、`dramatv-prod-media` |
| 访问域名 | 内网访问域名、外网 CDN 域名 |
| 上传方式 | 后端中转上传或预签名直传，建议预签名直传 |
| 下载方式 | 公共 CDN、私有签名 URL 或混合策略 |
| 跨域配置 | 前端直传时必须配置 CORS |

需要迁移到对象存储的资源：

- 视频源文件。
- 视频预览文件。
- 视频封面、poster、cover。
- 图片提示词示例图。
- 用户后续上传的图片、视频、附件。
- 画布 Runtime 中可见的图片、视频、缩略图、预览资源。

- `storage_provider`
- `bucket_name`
- `object_key`
- `public_url` 或 `cdn_url`
- `mime_type`
- `size_bytes`
- `duration_ms`
- `width / height`
- `checksum`

### 5.6 CDN

CDN 是内容分发网络，作用是把图片、视频、封面、预览等静态资源缓存到离用户更近的节点，降低源站带宽压力并提升加载速度。

这个项目需要 CDN 的原因：

- 视频和图片资源体积大，不能全部由应用服务器直出。
- 首页和精选页会大量展示封面和预览资源，CDN 能显著降低首屏和滚动加载压力。
- 用户上传内容增长后，如果不走 CDN，源站服务器带宽和对象存储回源成本会很快上升。

需要确认：

- CDN 域名。
- CDN 回源地址。
- 是否支持 HTTPS。
- 缓存规则：封面、poster、preview、source 分别缓存多久。
- 刷新和预热方式。
- 是否有防盗链、Referer、签名 URL 或私有访问策略。
- 视频 Range 请求是否正常支持。

### 5.7 Nginx / 网关

建议入口规则：

| 路径 | 转发目标 | 说明 |
| --- | --- | --- |
| `/` | Next.js 前端 | 页面访问 |
| `/home`、`/featured`、`/discussions` 等 | Next.js 前端 | 前端路由 |
| `/api/*` | Spring Boot 后端 | 业务 API |
| `/actuator/health` | 后端健康检查，建议只内网 | 健康检查 |
| `/media/*` | 对象存储或 CDN | 正式上线后不建议由应用服务器长期承接 |

需要确认：

- 请求体大小限制，视频上传相关路径要单独放宽。
- 代理超时时间，上传、发布、画布复制任务不要被过早断开。
- 是否统一加 `X-Request-Id`。
- 是否透传真实客户端 IP，例如 `X-Forwarded-For`、`X-Real-IP`。
- 是否有路径重写规则。
- 是否开启 gzip / brotli。

### 5.8 日志、监控与告警

当前项目已要求 `requestId` 贯穿前后端。线上对接时需要运维提供日志采集和排障入口。

需要采集的日志：

- Nginx / 网关访问日志。
- Spring Boot 应用日志。
- Spring Boot 错误日志。
- Next.js 运行日志。
- Worker 任务日志。
- 数据库慢查询或错误日志。

建议的排障字段：

- `requestId`
- `userId`
- `videoId`
- `workflowId`
- `promptId`
- `postId`
- `draftId`
- `commentId`
- `runtimeId`
- `copyTaskId`
- `moderationTaskId`

需要确认：

- 日志平台地址。
- 日志保留周期。
- 是否有错误告警。
- 是否有接口耗时、CPU、内存、磁盘、带宽监控。
- 是否能按 `requestId` 搜索完整链路。
- 敏感字段是否会被脱敏。

### 5.9 队列与异步任务

当前本地阶段很多能力仍是同步或占位。上线前以下链路建议接队列：

- 视频上传后的转码。
- 封面抽帧。
- 短预览生成。
- 内容审核。
- 工作流复制到画布。
- 大量导入 YouMind 历史数据。

需要确认：

- 公司是否已有消息队列，例如 RabbitMQ、Kafka、RocketMQ、Redis Stream、云队列。
- 是否允许先用简单队列方案过渡。
- 队列消费失败如何重试。
- 死信队列如何查看和处理。
- 任务状态是否需要在管理后台展示。

## 7. 登录系统对接

当前本地登录账号只用于开发和演示，后续要以公司画布产品登录为主。

需要和公司登录 / 画布团队确认：

- 当前画布登录使用什么协议：JWT、Session、OAuth2、OIDC、SSO 或公司内部网关。
- 社区是独立登录，还是完全复用画布登录态。
- 登录成功后社区能拿到哪些用户字段。
- 用户 ID 是否和画布用户 ID 一致。
- 是否有用户空间、组织、团队、角色等概念。
- Token 如何刷新。
- 退出登录是否需要同步退出画布。
- 社区后端如何校验 token。
- 社区是否需要支持游客浏览、登录用户、创作者、运营管理员多角色。

建议原则：

- 社区不要长期维护一套和画布割裂的正式账号体系。
- 社区本地 `users` 表可以保留为用户资料和账号映射表。
- 登录权威来源以后续公司画布登录系统为准。

## 9. 发布与部署流程确认

需要和运维确认：

- 前端如何构建：`npm run build`。
- 前端如何启动：`next start` 或容器化启动。
- 后端如何构建：Maven 打包。
- 后端如何启动：Java 17+ 运行 Spring Boot Jar 或容器化启动。
- 是否使用 Docker 镜像仓库。
- 是否有 CI/CD。
- 环境变量在哪里配置。
- 密钥是否通过 KMS、Secret Manager 或运维平台注入。
- 发布时是否需要数据库迁移审批。
- 回滚策略是什么。
- 静态资源发布是否需要 CDN 刷新。

建议最小发布链路：

1. 构建前端产物。
2. 构建后端 Jar 或镜像。
3. 执行数据库迁移。
4. 部署后端。
5. 部署前端。
6. 检查健康接口。
7. 做主路径 smoke。
8. 如失败，按版本回滚应用，数据库迁移按预案处理。

| --- | --- |
| `DRAMATV_STORAGE_PROVIDER` | 对象存储类型 |
| `DRAMATV_STORAGE_BUCKET` | Bucket 名称 |
| `DRAMATV_STORAGE_ENDPOINT` | 对象存储 Endpoint |
| `DRAMATV_STORAGE_CDN_BASE_URL` | CDN 访问域名 |
| `DRAMATV_STORAGE_ACCESS_KEY` | 访问密钥，必须走 Secret 管理 |
| `DRAMATV_STORAGE_SECRET_KEY` | 访问密钥，必须走 Secret 管理 |

## 11. 运维对接问题清单

## 12. 上线前验收清单

### 12.1 基础服务

- 前端页面可访问。
- 后端健康检查通过。
- 数据库连接正常。
- Redis 连接正常。
- 日志能正常采集。
- HTTPS 正常。
- `/api/*` 反代正常。

### 12.2 主路径

- 游客可以访问 `/`、`/home`、`/featured`、`/discussions`。
- 未登录点击发布、点赞、收藏、评论、画布入口会触发登录。
- 登录后可以发布帖子。
- 发布后的帖子能在讨论广场看到。
- 登录后可以发布视频。
- 发布后的视频能进入详情页。
- 视频、提示词、工作流、帖子可以点赞、收藏、评论。
- 作者主页和个人中心数据正常。

### 12.3 媒体资源

- 视频可播放。
- 图片可展示。
- CDN 地址可访问。
- 视频 Range 请求正常。
- 大文件上传不被 Nginx 或网关截断。
- 对象存储权限不暴露永久密钥。

### 12.4 排障能力

- 前端请求携带 `X-Request-Id`。
- 后端响应返回 `requestId`。
- 后端日志能查到同一个 `requestId`。
- 关键失败能看到错误码、可显示文案和 `requestId`。
- 登录、上传、发布、评论、画布入口至少能定位到用户和业务对象 ID。

## 13. 当前建议的对接顺序

1. 先确认测试环境的服务器、域名、Nginx、PostgreSQL、Redis。
2. 把当前前后端部署到测试环境，先不接 OSS，确认页面和 API 主路径可用。
3. 接对象存储和 CDN，把本地 YouMind 图片、视频和提示词资源迁移出去。
4. 把上传链路改成预签名或受控上传，停止依赖本地 `tmp/media`。
5. 接公司画布登录，替换当前本地登录。
6. 接媒体处理队列和 Worker，补转码、封面抽帧、预览生成。
7. 后续再接审核后台、运营后台、真实画布复制和监控告警面板。

## 14. 当前结论

如果公司只先给一台小服务器，DramaTV 社区可以先跑起来，但这只能作为测试或早期演示环境。

真正接近上线时，至少要把以下能力拆出去：

- 数据库：使用稳定 PostgreSQL 实例并开启备份。
- 缓存：使用稳定 Redis。
- 媒体：使用对象存储，不长期放服务器磁盘。
- 分发：视频、图片、封面走 CDN。
- 入口：通过 Nginx / 网关统一 HTTPS 和反代。
- 日志：接入统一日志平台，支持 `requestId` 排障。

社区当前最关键的上线差距，不是页面，而是媒体存储、登录对接、部署体系、日志监控、审核后台和画布真实联动。
