# 测试 ECS 三项目共享现状说明

创建日期：`2026-06-11`
适用环境：`8.141.20.130` 共享测试 ECS

## 1. 文档目的

这份文档用于收口当前测试服务器的真实状态，避免后续再把以下几类问题混在一起：

- 社区项目自身故障
- Nginx Host 分流错误
- 同机其他项目影响
- 阿里云备案 / 接入校验拦截
- ECS 防火墙与阿里云安全组放行不一致

当前结论先写在最前面：

- 这台测试机上当前同时承载 `3` 个项目
- 三个项目共享同一台 ECS
- 三个项目主要共享 `:80` 公网入口，通过 `Nginx server_name` 做域名级分流
- `DramaTV 社区` 当前服务本身是正常的
- 社区当前公网主入口 `community.8.141.20.130.nip.io` 被阿里云备案 / 接入校验页拦截
- 这不是社区前后端代码故障，而是公网入口合规性问题

## 2. 服务器与共享方式

### 2.1 共享机器

- ECS 公网 IP：`8.141.20.130`
- 运行方式：单机承载多个项目
- 入口层：`Nginx`

### 2.2 当前共享模式

当前主要是这两种共享：

1. 共享同一台 ECS
2. 共享 `:80` 公网入口

在 `:80` 上不是靠路径硬拆项目，而是靠不同 `Host / server_name` 分流：

- `community.8.141.20.130.nip.io` -> 社区
- `dramaloom.8.141.20.130.nip.io` -> DramaLoom
- `novel-similarity.8.141.20.130.nip.io` -> 法务相似度项目

## 4. 当前 Nginx 分流状态

### 4.1 已确认的 `server_name`

当前云端配置已确认：

- 社区：`server_name community.8.141.20.130.nip.io;`
- DramaLoom：`server_name dramaloom.8.141.20.130.nip.io;`

这意味着：

- 当前已经不是“社区因为 `server_name _` 抢兜底”或“被同事项目错误吃掉 Host”的阶段

### 4.2 特殊项

这个 `_` 只作用在 `3116`，不直接影响三个 `nip.io` 域名在 `:80` 上的相互路由。

## 5. 当前社区项目的真实故障点

### 5.1 不是应用故障

已确认：

- 社区前台、后台、后端服务都处于 `active`
- ECS 内部访问社区 `/` 与 `/login` 返回 `200`
- 社区精选 API、媒体代理也能正常返回

所以：

- 社区代码当前不是“挂了”
- 这次用户看到的白页、拦截页、502，不能直接归因到社区前后端业务逻辑

### 5.2 当前真正的问题

当前真正卡住的是：

- `community.8.141.20.130.nip.io` 这个公网业务入口不再稳定可用

具体现象：

1. 通过本机公网访问社区 `nip.io` 域名时，会进入阿里云“域名暂时无法访问 / 当前备案状态不符合访问要求”页面
2. ECS 内部带同样 `Host` 头访问时，应用返回正常

这说明：

- 拦截发生在应用之前
- 问题在阿里云备案 / 接入校验层
- 不是社区 Nginx、Next.js、Spring Boot 自身返回的页面

## 6. 为什么会这样

当前社区项目的测试入口使用的是：

- `community.8.141.20.130.nip.io`

而当前机器又是：

- 阿里云中国内地 ECS

这类入口一旦不满足阿里云当前的备案 / 接入口径，就会被入口层拦截。

因此当前局面可以概括为：

- 一台共享 ECS
- 三项目共享 `:80`
- 三项目靠不同域名分流
- 其中社区当前使用的 `nip.io` 入口被阿里云拦截

问题不在“共享 ECS 本身”，而在“社区当前公网域名入口不合规 / 不可用”。

## 7. 当前已经采取的临时恢复方案

为不影响另外两个项目的 `:80` 域名入口，已经为社区单独增加临时高位端口入口：

- 前台：`http://8.141.20.130:8086/login`
- 后台：`http://8.141.20.130:8206/admin/login`

相关配置：

- Nginx 新配置：`/etc/nginx/conf.d/dramatv-community-temp-ports.conf`
- 本地维护脚本：`scripts/open-test-community-temp-ports.ps1`

当前服务器内已确认：

- `8086` 与 `8206` 上 Nginx 已监听
- `firewalld public` 已放行：
  - `8086/tcp`
  - `8206/tcp`

## 8. 临时端口方案为什么仍可能失败

即使机器内已经监听、系统防火墙也已放行，外部浏览器访问临时高位端口仍可能失败。

当前最可能的原因不是社区应用本身，而是：

- 阿里云 ECS **安全组入站规则** 还没有同步放行 `8086` 与 `8206`

也就是说当前有两层放行：

1. ECS 机器内部 `firewalld`
2. 阿里云控制台安全组

当前已处理的是第 `1` 层；第 `2` 层仍需在阿里云控制台核查。

建议新增入站规则：

- `TCP 8086`
- `TCP 8206`

## 9. 后续建议

### 9.1 短期建议

用于尽快恢复测试访问：

1. 在阿里云安全组中放行：
   - `8086/tcp`
   - `8206/tcp`
2. 使用临时端口继续测试社区

### 9.2 中期建议

如果仍需要共享这台 ECS：

1. 保持三项目继续共用一台 ECS
2. 保持各项目使用独立域名做 `server_name` 分流
3. 不再把社区的业务入口继续依赖在当前 `nip.io` 测试域名上

### 9.3 长期建议

社区正式稳定入口应切换到：

- 公司主体下的合规域名
- 已完成正确备案 / 接入的域名

不建议长期依赖：

- 个人域名 + 公司 ECS
- `nip.io` 类测试域名直接承担中国内地阿里云正式业务入口
