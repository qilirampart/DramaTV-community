# 共享 ECS 公网入口现状总结

创建日期：`2026-06-11`
适用环境：`8.141.20.130` 共享测试 ECS

## 1. 结论先行

当前不是社区应用本身挂了，而是共享 ECS 的公网入口条件变了。

- 这台测试 ECS 只有 `1` 个公网 IP：`8.141.20.130`
- 这台 ECS 当前同时承载 `3` 个项目
- 多项目共用 `:80` 没问题，但前提是每个项目都要有可用的独立域名，通过 `Nginx server_name` 做 Host 分流
- 社区原来的 `community.8.141.20.130.nip.io` 入口现在会被阿里云备案 / 接入校验页拦截
- 新尝试的 `skpy.ltd` 也会被同类拦截，因为当前没有可用的备案 / 接入备案状态
- 裸 IP `http://8.141.20.130` 仍然可以从公网访问，但它只能作为一个默认站点入口，当前实际落到同事的 `DramaLoom`
- 因此，社区当前不能再把裸 IP `:80` 当成自己的稳定公网入口

一句话总结：

> 当前问题不是“服务器只能挂一个项目”，而是“共享 ECS 上只剩一个稳定的裸 IP `:80` 入口，而裸 IP 入口无法同时为多个项目做业务分流”。

## 2. 当前三项目分布

### 2.1 DramaTV 社区

- 前台进程：`127.0.0.1:3106`
- 后台进程：`0.0.0.0:3206`
- 后端进程：`0.0.0.0:18080`
- 目标公网 Host：`community.8.141.20.130.nip.io`
- 社区 Nginx 配置：`/etc/nginx/conf.d/dramatv-community-http.conf`

### 2.2 DramaLoom

- 目标公网 Host：`dramaloom.8.141.20.130.nip.io`
- 当前裸 IP `http://8.141.20.130` 的默认入口实际落在这个项目

### 2.3 法务相似度项目

- 目标公网 Host：`novel-similarity.8.141.20.130.nip.io`

## 3. 共享方式到底是什么

当前这台 ECS 的共享方式是：

1. 三个项目共用同一台 ECS
2. 三个项目共用同一个公网 IP
3. 三个项目理论上可以共用同一个 `:80`
4. 真正把三个项目区分开的，不是端口，而是域名 `Host`

也就是说：

- `:80` 不是只能挂一个项目
- `裸 IP :80` 只能稳定落到一个默认站点
- `多项目共存` 的关键是“每个项目有独立可用的域名做 Host 分流”

## 4. 为什么之前看起来可以

之前之所以“像是一直能用”，并不代表那时就是长期合规的正式公网入口。

真实情况更接近：

- 社区当时使用的是 `http://community.8.141.20.130.nip.io`
- 这是公网域名访问，不是内网访问
- 只是当时这条入口还没有被阿里云入口层拦截，所以看起来一直可用

到了 `2026-06-11`，情况发生变化：

- ECS 内部带 `Host` 访问社区页面仍然返回 `200`
- 外部走 `community.8.141.20.130.nip.io:80` 时，会直接命中阿里云“域名暂时无法访问 / 当前备案状态不符合访问要求”页面

这说明：

- 社区代码没有挂
- 社区 Nginx 主链路没有挂
- 变化发生在公网入口合规层，而不是应用层

## 5. 为什么现在裸 IP 也不能拿来当社区入口

当前 `http://8.141.20.130/login` 会跳到同事项目，不是偶发现象，而是共享 ECS 下的正常结果。

原因是：

- `8.141.20.130` 是裸 IP，不是社区域名
- 请求头里的 `Host: 8.141.20.130` 不匹配社区的 `server_name community.8.141.20.130.nip.io`
- 因此它不会落到社区站点，而会落到当前默认站点
- 当前默认站点已经被同事项目接住

所以：

- 裸 IP `:80` 可以证明“这台机器公网还活着”
- 但不能证明“社区还能公网访问”
- 更不能把它继续当作社区正式业务入口

## 6. 当前实际卡点

社区当前卡点有两个层次：

### 6.1 业务域名入口不可用

当前社区和新尝试的个人域名都遇到同类问题：

- `community.8.141.20.130.nip.io` 被阿里云备案 / 接入校验拦截
- `skpy.ltd` 也被同类校验拦截

这意味着：

- 共享 ECS 上“靠域名分流社区”的主方案暂时失效
- 不解决合规域名问题，社区无法恢复正常 `:80` 公网访问

### 6.2 临时高位端口方案可能还差安全组放行

当前已为社区准备过临时恢复方案：

- 前台：`http://8.141.20.130:8086/login`
- 后台：`http://8.141.20.130:8206/admin/login`

服务器内侧已落地：

- Nginx 临时配置：`/etc/nginx/conf.d/dramatv-community-temp-ports.conf`
- 机器内 `firewalld` 已为 `8086/tcp`、`8206/tcp` 放行

外部如果仍然访问不了，最可能原因是：

- 阿里云控制台的 ECS 安全组入站规则还没有同步放行 `8086/tcp`
- 阿里云控制台的 ECS 安全组入站规则还没有同步放行 `8206/tcp`

## 7. 当前可以怎么恢复

### 7.1 短期恢复测试

短期最现实的方案不是继续纠结 `:80`，而是：

1. 让运维确认并放行 ECS 安全组入站规则
2. 开放：
   - `TCP 8086`
   - `TCP 8206`
3. 社区先通过高位端口继续联调和测试

这个方案的优点是：

- 不影响同事现有项目
- 不需要改动 `:80` 默认站点
- 不需要立刻完成正式域名备案

### 7.2 中长期恢复正式公网访问

如果社区要恢复标准公网访问，必须回到“独立域名 + Host 分流”这条正路。

需要满足：

1. 给社区分配真实可用的正式域名
2. 该域名能够在当前阿里云中国大陆 ECS 上完成备案或接入备案
3. 运维把该域名挂到社区自己的 `server_name`
4. 社区、DramaLoom、法务项目继续共用 `:80`，但按不同域名分流

## 8. 这是不是服务器不够用

不是。

当前问题和服务器“能不能承载三个项目”不是一回事。

更准确地说：

- 如果这台 ECS 上只有一个项目，那么只用 `http://8.141.20.130` 这个裸 IP 入口，技术上通常够用
- 但只要这台 ECS 上有多个项目，裸 IP 就不够，因为它无法区分“要进哪个项目”
- 多项目共用一台 ECS 时，核心不是算力够不够，而是公网入口分流是否成立

所以当前真正不够的不是机器资源，而是：

- 可用的多项目公网入口条件

## 9. 建议找谁

### 9.1 公司运维 / 云资源负责人

需要确认：

- 这台 ECS 的公网入口策略
- 当前 `:80` 默认站点归属
- 临时高位端口 `8086/8206` 的安全组放行
- 后续社区正式域名的挂载方式

### 9.2 公司备案经办人 / 域名负责人

需要确认：

- 是否有公司主体下可用于社区的正式域名
- 该域名是否已备案
- 如果已备案，能否在当前阿里云实例上做接入备案
- 如果未备案，是否准备新增备案
