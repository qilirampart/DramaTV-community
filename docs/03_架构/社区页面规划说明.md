# DramaTV 社区页面规划说明

这份文档用于配合 `社区页面规划图.drawio` 一起看。

对应图文件：

- `docs/03_架构/社区页面规划图.drawio`

## 1. 为什么要先画这张图

在正式开始前端重构之前，最大的风险不是“不会写页面”，而是：

- 一会儿像官网
- 一会儿像普通短视频 feed
- 一会儿又像工作流工具后台

所以这张图先解决两个问题：

1. 我们到底借鉴哪些优秀社区
2. 五个核心页面各自应该承担什么职责

## 2. 还记得的优秀社区案例，以及它们分别给我们的启发

### 2.1 Runway

我们借它：

- 首页首屏的“精选片场感”
- 视频内容优先的电影化呈现
- 高质量视频社区不只靠瀑布流，还要有栏目、征集和精选感

我们不照抄：

- 纯品牌展示式官网叙事
- 过度依赖大视觉、弱化信息结构

### 2.2 TapTap

我们借它：

- 内容对象详情页的结构感
- 评论区和讨论区围绕对象展开
- 作者 / 开发者主页不是装饰页，而是承接关系的页面

我们不照抄：

- 游戏商店感
- 下载分发和评分体系

### 2.3 LiblibAI

我们借它：

- 作品、工作流、创作者中心可以在同一平台里并行成立
- 发布页未来可以逐步演进为创作者中心
- 工作流必须作为一级对象运营

我们不照抄：

- 过重的工具导航集合
- 过早引入商业化、授权和复杂资源中心

### 2.4 RunningHub

我们借它：

- 工作流不只是“看”，还可以“复制”“运行”“回到画布”
- 工作流详情页应该有明确的主操作

我们不照抄：

- 过强的工具与算力平台气质
- 让社区退化成工作流控制台

### 2.5 Pinterest

我们借它：

- 首页发现流和卡片陈列节奏
- 作者主页中作品和工作流的浏览感

我们不照抄：

- 暖白生活方式视觉
- 红色品牌主导

## 3. 五个核心页面的规划

## 3.1 社区首页

首页不应该是工具官网，也不应该是普通短视频流。

首页规划：

- `Hero`：精选片场、本周主题、社区主张
- `推荐流`：优先分发作品，同时带作者和来源工作流信号
- `热门工作流`：方法对象一级露出
- `创作者入口`：作者和专题
- `讨论 / 挑战 / 栏目`：为社区运营层预留
- `创作入口`：开始发布、查看工作流、回到画布

## 3.2 视频详情页

视频详情页是“看结果，再回到方法”的第一跳。

页面规划：

- 主视频区
- 标题、简介、标签、提示词摘要
- 作者信息和关注动作
- 来源工作流区
- 评论区
- 相关推荐

## 3.3 工作流详情页

工作流详情页不是视频附件页，而是方法对象页。

页面规划：

- 工作流头部信息
- 主操作：复制工作流 / 在画布中打开
- 方法说明和依赖说明
- 关联作品
- 作者信息
- 版本、评论、可见性说明

## 3.4 作者主页

作者主页不是普通用户资料页，而是“创作者片场”。

页面规划：

- 作者头部：身份、风格标签、关注动作
- 作品区
- 工作流区
- 创作叙事和代表内容
- 社区关系与专题推荐

## 3.5 发布页

发布页不再按“简单上传表单”理解，而按“创作者工作台”理解。

页面规划：

- 发布类型选择
- 媒体上传
- 基本信息
- 绑定工作流
- 状态区：草稿 / 待审核 / 已发布
- 主动作：保存草稿 / 提交审核 / 预览落点

## 4. 页面之间的主路径

当前最重要的用户路径仍然是：

`首页发现作品 -> 视频详情 -> 来源工作流 -> 作者主页 -> 创作者继续发布`

这条路径成立之后，后面再去做：

- 工作流复制到画布
- 运营活动
- 榜单和搜索
- 派生关系

才不会跑偏。

## 5. 这张图接下来怎么用

接下来前端重构时，这张图主要做三件事：

1. 防止首页被做成官网
2. 防止工作流页被做成附件页
3. 防止发布页被做成后台表单页

下一步实现顺序建议：

1. 先改全局样式和导航骨架
2. 再改首页
3. 再改视频详情页和工作流详情页
4. 然后改作者主页
5. 最后改发布页
