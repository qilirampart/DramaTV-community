# DramaTV 项目工程理解 - 第 1 课：从功能到实现链路

## 学习目标

本节结束后，你应该能做到：

- 不再只用“这个功能能不能用”来理解项目
- 能把一个功能拆成页面、接口、后端服务、数据库、运行环境五层
- 能用这套方法解释精选页、作者页、发布页这类主链路
- 遇到问题时，能先判断大概应该查哪一层

## 内容讲解

你现在对项目的功能比较熟，这是优势。真正让你没底的地方，不是“不知道精选页是什么”，而是还没有稳定形成这条因果链：

```text
用户看到的功能
-> 前端页面和组件怎么组织
-> 前端调用哪个 API
-> 后端哪个 Controller / Service 处理
-> 后端查哪些表或配置
-> 数据和媒体资源怎么回到页面
-> 本地和云端运行环境是否一致
```

以后你理解任何功能，都先按这五层拆。

## 第一层：页面层

页面层回答的是：

- 用户在哪个路由看到这个功能
- 页面由哪些主要组件组成
- 用户操作会触发什么前端状态变化

以精选页为例：

- 路由是 `/featured`
- 相关代码优先看 `apps/web/src/features/featured`
- 它不是普通列表页，而是包含分类切换、瀑布流、分页加载、返回定位的复杂页面

你以前可能会说：

- “精选页能看资源，也能切分类。”

更工程化的说法是：

- “精选页是一个列表状态复杂的资源浏览页面，前端要维护当前分类、已加载页、瀑布流排布、滚动位置和返回恢复状态。”

这两种说法的差别，就是功能理解和工程理解的差别。

## 第二层：接口层

接口层回答的是：

- 页面数据从哪个 API 来
- 请求参数是什么
- 返回结构是什么
- 前端是否做了二次映射

例如精选页常见入口包括：

- `GET /api/feed/featured`
- `GET /api/feed/featured-inventory`

这意味着它不是前端自己凭空生成卡片，也不是直接读数据库。前端页面通过 API 获取后端已经组织好的数据，再映射成卡片展示。

以后你看任何页面，先问自己：

```text
这个页面首屏数据从哪个接口来？
点击、切换、加载更多又打哪个接口？
接口返回的数据和页面展示字段是否一一对应？
```

## 第三层：后端服务层

后端服务层回答的是：

- API 入口在哪个 Controller
- 业务组织在哪个 Service
- 查询逻辑在哪个 QueryService 或 Repository
- 是否有权限、过滤、排序、分页、缓存

以精选页为例，后端优先看：

- `apps/server/src/main/java/com/dramatv/community/feed`
- `apps/server/src/main/java/com/dramatv/community/prompt`
- `apps/server/src/main/java/com/dramatv/community/shared`

你要养成一个习惯：

```text
看到一个 API，不要只停在 Controller。
Controller 通常只是入口，真正决定“查什么、怎么排、怎么过滤”的多半在 Service / QueryService。
```

## 第四层：数据层

数据层回答的是：

- 这个功能依赖哪些表
- 哪些表是内容真相
- 哪些表是运营编排
- 哪些表只是媒体元数据或互动关系

精选页可能涉及：

- `feed_items`
- `prompt_entries`
- `media_assets`
- `videos`
- `workflows`
- `admin_feed_slot_configs`

这里最重要的一点是：

```text
前台展示的列表，不一定直接等于某张内容表的全部数据。
```

比如后台配置、运营编排、内容状态、资源类型、分类过滤、媒体角色都会影响最终展示。

这也是为什么你之前会遇到“后台配置和前台展示不一致”“脏数据落到页面上”“分类里混入帖子”这类问题。它们不是单纯 UI 问题，而是分发层、治理层、内容真相层没有对齐。

## 第五层：运行环境层

运行环境层回答的是：

- 本地和云端是不是同一套数据
- 域名是否打到正确项目
- Nginx 是否把请求分到正确服务
- 服务是否真的重启到了新 release
- 媒体资源路径是否可访问

你们这个项目有一个很典型的现实复杂度：

- 本地有 `3106 / 3206 / 18080`
- 云端有 `drama-community-dev.dzkjm.cn`
- 同一台 ECS 上还有别的项目
- 历史域名、临时端口、裸 IP 都曾参与过排障

所以以后遇到“页面不对”，不能马上判断是代码错了。你要先问：

```text
我现在访问的是正确域名吗？
请求有没有打到社区项目？
前台、后台、后端是不是同一批 release？
数据库和媒体资源是不是云端真实数据？
```

## 用一句话建立你的新理解

以前你看功能，可能是：

```text
这个页面有某个功能。
```

现在你要升级成：

```text
这个功能由前端页面状态、API 契约、后端服务查询、数据库关系、运行环境共同组成。
```

只要你开始这样拆，项目就不会再是一团大雾。

## 小结

- 一个功能不是一个孤立按钮或页面，而是一条跨层链路。
- 推荐先用五层法理解：页面层、接口层、后端服务层、数据层、运行环境层。
- 精选页是最适合学习的样本，因为它包含分类、分页、媒体、后台配置、返回定位和云端数据差异。
- 你当前最需要补的不是泛泛学框架，而是把已做出的功能反向拆成实现链路。
