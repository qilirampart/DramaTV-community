# DramaTV 社区项目新会话快速恢复指南

更新日期：2026-04-15

## 1. 这份文档是干什么的

这份文档不是长期架构文档，也不是产品方案。

它的目标只有一个：

- 让下一个新聊天在最短时间内恢复上下文
- 明确现在代码里真实做到了什么
- 明确还有哪些事情没做完
- 明确下一步应该先做什么，而不是继续沿着错误判断往前推

这份文档尤其用于处理当前这个现实问题：

- 聊天已经很长，旧上下文会被压缩
- 最近几轮做了不少页面重构和文档整理
- 但用户最新反馈很明确：`“实际我没有看到一点视觉效果的迁移”`

因此，后续新会话不能直接沿用“视觉迁移已经明显成立”的判断，而必须把这条反馈当成新的校准基线。

---

## 2. 当前项目基线

### 2.1 正式工程主线

当前正式主线不是旧原型，也不是新开的第二套前端，而是：

- 前端：`apps/web`，`Next.js + React + TypeScript`
- 后端：`apps/server`，`Spring Boot`
- AI / 媒体 / 工作流异步处理：`Python Worker / FastAPI`

已经明确不再把根目录旧的 `React + Vite` 页面原型当成正式主线。

### 2.2 当前产品口径

当前必须锁死的产品口径：

- 社区主内容是视频
- 工作流不是独立一级内容线，而是和视频绑定展示
- 讨论区是独立内容线
- 发布当前先做两种：
  - 发布视频，可选绑定工作流
  - 发布帖子，帖子单独存在
- 个人中心已是正式需要承接的页面
- `/nano-banana` 和 `/seedance` 是社区里的独立资源页，用来承接图片提示词和视频提示词流量

### 2.3 当前开发方式

当前已经进入全链路开发阶段，不再以 mock 为验收标准：

- 前端尽量走真实请求
- 后端走真实 JDBC / PostgreSQL
- 交互验收优先看真实 API 与真实数据库结果

## 3. 先记住这几个“不要再走错”的约束

### 3.1 不要再开第二套正式前端

已经做过技术栈判断，结论固定：

- 不切到正式 `React + Vite`
- 继续在 `apps/web` 内重构
- 同事的 `mindloop-_-cinematic-archive (1)` 只作为视觉参考，不作为新的正式运行架构

### 3.2 不要把工作流重新做成独立内容线

用户已经明确纠正过：

- 工作流一定是和视频一起的
- 不需要单独展示为一级内容线
- 不要再往“独立工作流发现页 / 作者页独立工作流区”这个方向写产品判断

### 3.3 不要把“代码改了”误判成“视觉迁移成功了”

这是当前最关键的修正点。

虽然最近确实做了首页和视频详情页的结构改写、样式补充、构建验证，但用户最新反馈是：

- 实际没有感知到明显视觉迁移

因此后续新会话必须按下面这个口径继续：

- 已经做过一轮页面结构与样式尝试
- 但用户不认可当前视觉迁移效果
- 所以下一步不是继续“默认这轮成功”，而是重新做运行态对照、视觉提炼和更明显的迁移落地

## 5. 当前没有完成、或者判断不能乐观化的部分

这一段最重要，因为它会决定新会话的第一步。

### 5.1 当前最大问题：视觉迁移没有被用户感知到

这条不能弱化。

用户最新明确反馈是：

- `“实际我没有看到一点视觉效果的迁移”`

这意味着：

- 不能继续在新会话里说“首页和详情页视觉迁移已经成功”
- 不能继续按“剩下几页照这个风格铺开”来推进
- 必须先回到运行态页面，对照同事参考项目，重新提炼到底哪些视觉特征还没有真正迁进去

### 5.2 当前更像“局部结构改写”，还不像“明显的新视觉系统”

目前实际发生的问题大概率是：

- JSX 结构改了一些
- `globals.css` 也补了一些
- 但整体视觉识别度不够强
- 页面之间没有形成足够鲜明、统一、可感知的新的设计系统

换句话说：

- 代码确实动了
- 但用户感知层没有形成“这就是新版本”的强信号

### 5.3 浏览器级验收这轮没有闭环

虽然构建和健康检查都过了，但最近一轮视频详情页重构后，浏览器级快照没有补上，原因是：

- Playwright MCP 会话被现有浏览器实例锁住

这意味着：

- 这轮缺少一组新的运行态截图证据
- 也就缺少了和用户主观反馈对照的客观材料

### 5.4 还有一些主线页面没有进入真正的视觉统一状态

虽然碰过多页，但从“用户能明显看出来换代”的标准看，当前还远远不够：

- 作者页不算完成
- 个人中心不算完成
- 发布页不算完成
- 讨论页不算完成

更准确地说：

- 它们属于已经做过产品收口和局部页面调整
- 但还不属于“视觉系统已经迁移成功”

## 6. 新会话里第一优先级应该做什么

不要直接继续散着改页面。

先做下面这件事：

### 6.1 第一任务：重新建立“视觉迁移验收基线”

新会话第一步建议不是继续写代码，而是先做这 4 步：

1. 把当前运行中的首页、视频详情页、作者页、个人中心页截运行态图
2. 把同事参考项目 `mindloop-_-cinematic-archive (1)` 的关键视觉特征拆出来
3. 明确我们这边到底缺了哪些“肉眼可感知”的视觉迁移动作
4. 写成一个简短的“视觉迁移差距清单”

这一步做完，才能继续真正改版。

### 6.2 第二任务：先做“视觉基线”，再做页面铺开

建议新会话不要再直接说“开始改作者页/改个人中心页”，而要先把视觉基线重新提出来，例如：

- 字体组合到底用什么
- 标题风格到底怎么统一
- 页面背景和层次怎么处理
- 卡片系统到底是更偏 editorial、cinematic，还是更偏 archive、gallery
- 动效和 hover 的主语气是什么
- 哪些元素必须形成全站统一识别

如果这一层没做清楚，继续改页面只会重复“代码变了，但用户没感觉”。

### 6.3 第三任务：按这个顺序推进

建议新会话优先级按这个顺序：

1. 首页与视频详情页重新做一轮真正可感知的视觉迁移
2. 作者页
3. 个人中心页
4. 发布页
5. 讨论页

原因：

- 首页和视频详情页是用户最容易感知“版本升级”的两页
- 作者页和个人中心页承接主路径后的深度浏览
- 发布页和讨论页更偏功能页，可以在视觉基线稳定后再铺开
