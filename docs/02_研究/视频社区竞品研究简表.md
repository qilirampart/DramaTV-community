# 视频社区竞品研究简表

更新日期：2026-04-06  
研究目标：为“AI 视频生成社区 + 画布工作流社区”提炼可直接借鉴的产品机制，避免只参考单一社区形态。

## 1. 我们要做的不是哪一种社区

这个项目不应被定义为：

- 纯短视频社区
- 纯作品展示站
- 纯 AI 工具站
- 纯模板资源站

更准确的定位应是：

- 作品社区
- 工作流社区
- 创作者社区
- 讨论社区

也就是：`视频作品 + 画布工作流 + 作者主页 + 讨论互动 + 派生复用`

## 2. 优先参考项目

| 项目 | 最值得借的能力 | 不建议照抄的部分 | 对我们的启发 |
|---|---|---|---|
| TapTap | 条目页、评论讨论、榜单分区、开发者页、社区与内容对象强绑定 | 过重的游戏商店属性、下载分发逻辑 | 把“视频作品”和“工作流”都做成独立条目，而不只是 feed 卡片 |
| LiblibAI | 模型/工作流/教程/API/创作中心一体化，创作者可发布资源与工作流 | 过强的平台内生成功能容易让社区退化成工具入口集合 | 社区可以同时承载“工具入口 + 资源发布 + 创作者成长”，发布中心应面向作品与工作流双对象 |
| Figma Community | 模板/插件/资源可发布、可发现、可复用、可售卖 | 过强的工具导向和审核链路直接搬运 | 工作流应是一级内容，不是视频详情页的附件 |
| Midjourney | Explore 流、热门排序、详情页展示 creator/prompt/settings、复用入口 | 过强的公开默认机制可能不适合早期创作者 | 作品详情页应展示创作方法，而不只展示成片 |
| Hugging Face Spaces | repo-backed、可复制、可派生、可见性分级 | 过于偏开发者的仓库心智 | 工作流应支持复制、派生、版本化 |
| OpenArt | 工作流广场、创作者作品社区、模型与视频工具结合 | 产品路线摇摆时，工作流社区可能被边缘化 | 工作流社区必须是主线能力，不能只是营销补充 |
| RunningHub | 云端 ComfyUI 工作台、工作流社区、AI 应用发布、API 直连 | 工具和算力导向极强，普通用户浏览体验相对弱 | 工作流不只是展示对象，还可以成为可运行、可复制、可接 API 的生产单元 |
| Krea | 工具与社区一体化、社区 Apps、样式库、画布式编辑 | 功能面过宽，容易稀释社区主线 | 社区可与画布软件联动，形成风格预设、模板、社区小工具 |
| Runway | 精选、赛事、扶持、荣誉体系、品牌化社区活动 | 过度依赖活动运营，不适合作为基础结构 | 高质量视频社区不能只有 feed，还要有精选与活动机制 |

## 3. 官方资料里的关键信号

### 3.1 TapTap

官方移动页显示，TapTap 把自己定义成“发现值得玩的游戏”的平台，并明确强调：

- 超过 `120,000+` 游戏库
- `Reviews and discussions`
- `60 Thousand` 开发者入驻
- 用户可以为游戏留下评论，分数由社区反馈持续更新

这说明它不是“商店 + 评论区”，而是“内容对象 + 社区互动 + 创作者/开发者主页”的组合。

对我们的可借点：

- 视频作品要有独立详情页
- 工作流也要有独立详情页
- 作者页不只是头像页，而是运营页
- 评论和讨论应该围绕对象展开，而不是只有统一评论池

来源：

- https://www.taptap.io/mobile
- https://developer.taptap.io/docs/store/
- https://developer.taptap.io/docs/store/store-faq/

### 3.2 Figma Community

Figma 官方条款和帮助文档明确说明：

- Community 是分享和获取模板、插件、widget 等资源的平台
- 资源可以分享，也可以销售
- 发布 App 到 Community 需要提供 listing、封面、描述、标签、测试说明，并经过审核
- 售卖资源有平台支持、退款支持、税务处理，但当前不再批准新的付费文件创作者

对我们的可借点：

- 工作流、模板、预设、插件型能力都可以是一级资源
- 发布内容不能只有上传文件，必须有 listing 结构
- 资源型内容应区分免费、付费、预览、试用

对我们的提醒：

- 审核链路一旦做重，会显著增加运营成本
- 收费体系必须足够清楚，否则会让社区混乱

来源：

- https://www.figma.com/legal/community-terms/
- https://help.figma.com/hc/en-us/articles/35074258201495-Publish-apps-to-the-Figma-Community
- https://help.figma.com/hc/en-us/articles/12067637274519-About-selling-Community-resources
- https://help.figma.com/hc/en-us/articles/11786473291159-Purchase-Community-resources

### 3.3 Midjourney

Midjourney 官方文档说明：

- Explore 页支持 `For You`、`Random`、`Hot`、`Top`
- 点击作品可看到 creator、prompt、settings
- 悬停可直接复用图片和 prompt
- 还有 Likes、Style Explorer、Rooms 等社区发现与互动层

对我们的可借点：

- 首页推荐流要同时支持个性化、随机发现、热门、时间榜
- 作品详情页要暴露创作元信息
- 作品不仅可看，还应可继续创作、复用、派生

对我们的提醒：

- 如果默认完全公开，很多早期创作者会担心被抄
- 私密/公开/仅自己可见的层级要产品化，而不是临时功能

来源：

- https://docs.midjourney.com/docs/explore-page
- https://docs.midjourney.com/hc/en-us/articles/33329460426765-Website-Overview
- https://docs.midjourney.com/hc/en-us/articles/28014645615373-Keeping-Your-Creations-Private

### 3.4 Hugging Face Spaces

官方文档说明：

- Spaces 本质上是 repo-backed
- 每次新 commit 会自动 rebuild 和 restart
- 支持 public、protected、private 三种可见性
- 支持 clone 和 duplicate 的协作心智

对我们的可借点：

- 工作流不应只是图片或 JSON 附件，而应是可复制的创作单元
- 工作流页面应支持“复制一份继续改”
- 公开、受保护、私有这三种可见性分层很值得借鉴

对我们的提醒：

- 如果工作流过于偏工程对象，普通用户会被门槛挡住
- 需要做“轻浏览”和“深编辑”两层体验

来源：

- https://huggingface.co/docs/hub/spaces-overview

### 3.5 OpenArt

OpenArt 官方关于页说明它既是 AI 艺术平台，也有用户上传发现流。它的 workflows 页面曾经把 ComfyUI workflow 做成可浏览、可下载、可排序的社区内容，但官方页面也明确写出：

- `OpenArt Workflows 将于 2026-01-18 下线`

这是一个非常关键的反面经验。

对我们的可借点：

- 工作流社区和作品社区确实能形成强关联
- 创作者、模型、视频工具、workflow 可以出现在同一产品里

对我们的提醒：

- 工作流如果只是补充能力，很容易在业务聚焦时被砍掉
- 如果我们要做，就要把工作流作为主线对象长期经营

来源：

- https://openart.ai/about
- https://openart.ai/workflows/dev
- https://openart.ai/workflows/academy

### 3.6 Krea

Krea 官方页面和文档显示：

- 它同时覆盖 image、video、realtime、enhancer、edit、training
- 有 `1000+ styles`
- 有 `Community AI Apps`
- 有 canvas-based 的编辑方式

这类产品不是传统社区，但它证明了一件事：

- 工具和社区可以做成一体，而不必拆成两个完全独立的站

对我们的可借点：

- 未来可把画布软件和社区打通
- 社区里可以存在“风格预设”“社区 Apps”“社区工作流模板”
- 社区首页不只有作品流，也可以有可直接进入的工具入口

对我们的提醒：

- 工具过多会冲淡社区主线
- 首页不能做成“所有功能入口大合集”，否则会像工具官网，不像社区

来源：

- https://www.krea.ai/
- https://www.krea.ai/apps
- https://docs.krea.ai/get-started/what-is-krea
- https://www.krea.ai/features/video

### 3.7 Runway

Runway 当前最值得参考的不是普通社区 feed，而是它围绕 AI 视频创作者建立的荣誉和活动层：

- 2026 AI Festival 已是第四届
- 覆盖 Film、Design、New Media、Gaming、Advertising、Fashion 等类别
- 有现金奖励、Runway credits、评审、线下放映
- 2025 年官方新闻提到，AI Film Festival 收到 `6000+` 作品提交，并与 IMAX 做联动放映

对我们的可借点：

- 高质量 AI 视频社区不能只靠 feed，要有精选、征集、比赛、栏目、扶持
- 社区的“上升路径”要清晰，否则优秀作者不会沉淀

对我们的提醒：

- 活动机制只能建立在稳定社区结构之上
- 没有基础内容生态前，过早做大型赛事会失真

来源：

- https://aif.runwayml.com/
- https://runwayml.com/news/runway-imax-aiff-presentation
- https://runwayml.com/hundred-film-fund

### 3.8 LiblibAI

LiblibAI 当前给我们的价值，不只是“又一个 AI 社区”，而是它把创作工具、资源发布、创作者中心、API 和商业化授权放在了同一平台里。

官方用户协议在 `2026 年 3 月 10 日` 更新、`2026 年 3 月 17 日` 生效，并明确说明：

- LiblibAI 及其关联平台包括 `LibTV`、`星流`
- 同时覆盖网站、客户端、`SDK` 和 `API`
- 平台服务范围不只包括内容生成，也包括 `模型训练`、`信息发布`、`互动交流`、`搜索查询`
- 平台能力已覆盖 `文生图`、`文生视频`、`图生视频`

而在官方站内的工作流页面导航里，可以直接看到：

- 图片生成
- 视频生成
- WebUI
- ComfyUI
- 训练 LoRA
- AI 应用
- 创作中心
- 发布
- 教程
- API

这说明 LiblibAI 的核心思路不是“内容社区 + 一个工具入口”，而是更接近：

- 工具平台
- 资源社区
- 创作者中心
- API 能力平台

同时，LiblibAI 还有两个很值得注意的官方信号：

- 官方提供 `API` 开放平台服务条款，说明模型和工作流能力可以外部调用
- 官方存在“原创工作流许可协议”，说明工作流已被平台当作可展示、可销售、可许可的资源对象处理

对我们的可借点：

- 发布中心不应只是一张简单的上传表单，而应逐步演进成创作者中心
- 工作流不只是视频附件，而是独立资源对象，并且后续可能承接授权、复制、派生和商业化
- 社区里“方法”这层内容可以被产品化，而不是只靠评论区零散承接
- 工具、创作、发布、资源、API 可以做成一体，但要有主次

对我们的提醒：

- LiblibAI 的工具链很重，如果直接照搬，社区首页容易退化成“功能入口导航站”
- 模型训练、平台内生成、API、工作流授权这些能力会显著抬高产品复杂度
- 如果前期就引入过重的交易、授权、收费设计，会拖慢社区主路径建设

对全栈架构的启发：

- 需要尽早把 `发布服务`、`工作流服务`、`创作者中心`、`API 网关`、`资源授权边界` 分开考虑
- 社区内容如果未来要接 API 或商业许可，数据模型不能只停留在前端假数据层

### 3.9 RunningHub

RunningHub 当前最值得我们关注的，不是它像不像传统社区，而是它把 `云端 ComfyUI`、`工作流社区`、`AI 应用发布` 和 `API 调用` 连成了一条很完整的生产链路。

官方首页直接给出的信号包括：

- “在线开发 ComfyUI 工作流，发布 AI 应用并获得收入”
- “高品质 AI 工作流社区”
- 工作流支持“在线分享、学习、编辑和运行”
- 平台提供 API，让外部系统调用 RunningHub 工作流

官方 API 文档又进一步说明：

- RunningHub API 可以把云端 ComfyUI 工作流集成到自己的产品里
- 只要是在 RunningHub 上能正常运行的工作流，都可以通过 API 调用
- 调用前需要注册账号、开通基础版及以上会员、获取 Workflow ID
- Workflow 必须先在网页端手动成功运行过至少一次
- API 账户类型分为消费级、企业级共享、企业级独占
- 企业级共享默认支持 `100` 并发

这说明 RunningHub 不是把工作流当“静态资源”来做，而是把它当成：

- 可在线运行的生产单元
- 可发布成 AI 应用的封装单元
- 可被外部业务系统调用的服务单元

对我们的可借点：

- 工作流详情页后续不应只支持“查看说明”，还应支持“运行”“复制”“接回画布”
- 社区中的工作流如果足够成熟，可以进一步演进成应用或 API 能力
- “工作流对象”和“运行时对象”最好从一开始就区分开来
- 画布联动这件事不应只停留在跳转按钮，后续应预留真正的调用边界

对我们的提醒：

- RunningHub 的平台重心非常偏工具、算力和运行时，如果直接照搬，社区氛围会不足
- 它的会员、API Key、并发等级、运行计费等机制都属于平台中后期能力，不适合第一阶段照搬
- 一旦要走“工作流可调用”路线，权限、配额、日志、审计、安全和异步任务都会显著复杂化

对全栈架构的启发：

- 后续需要把 `工作流注册`、`工作流运行`、`异步任务`、`API 网关`、`鉴权与配额` 作为独立边界考虑
- 如果未来支持“作品绑定工作流并可复用”，媒体服务和工作流服务就不能混成一层

来源：

- https://www.runninghub.cn/
- https://www.runninghub.cn/runninghub-api-doc-cn/doc-8287334
- https://www.runninghub.cn/call-api/api-detail/2004544343584849921?activeTab=api

说明：

- “RunningHub 把工作流做成可运行、可发布、可接 API 的生产单元”这一结论，来自对官方首页与官方 API 文档的综合判断。

## 4. 适合我们直接借的产品机制

### 4.1 双核心内容对象

不要只做“视频帖子”。

建议同时建立两个一级对象：

- 视频作品
- 画布工作流

两者应互相关联，但都能独立浏览、独立评论、独立收藏。

### 4.2 双详情页结构

至少需要：

- 视频详情页
- 工作流详情页

而不是把工作流只作为视频详情页下方一个附件下载块。

### 4.3 创作者主页双视角

作者主页至少要分两个 tab：

- 作品
- 工作流

如果只展示作品，会削弱你们和普通视频社区的差异。

### 4.4 推荐流分层

首页推荐不要只有单一 feed，至少应支持：

- 推荐
- 热门
- 最新
- 工作流
- 关注

后期再考虑：

- 按主题分区
- 按模型分区
- 按创作方式分区

### 4.5 复用与派生机制

用户不应只是“看作品”。

应支持至少一种派生关系：

- 基于这个视频继续创作
- 基于这个工作流复制一份
- 在自己的画布中打开

这是你们和普通视频社区最关键的差异点。

### 4.6 公开性分级

建议从一开始就区分：

- 公开
- 仅链接可见
- 私有

并尽早为工作流设计：

- 是否允许复制
- 是否允许派生
- 是否隐藏参数

### 4.7 社区运营层

产品成熟后，建议加：

- 精选栏目
- 周榜 / 月榜
- 创作挑战
- 主题征集
- 认证创作者

这一层最适合借 Runway。

## 5. 不建议直接照搬的部分

### 5.1 不做纯游戏下载/分发平台

TapTap 的商店属性是游戏社区的历史结果，不适合直接搬到视频社区。

### 5.2 不做过重的审核和交易系统

Figma 的审核和收费体系很强，但那是一套成熟平台能力。你们前期应先做发布和复用，再谨慎上交易。

### 5.3 不做全站默认自动播放

AI 视频内容天然重。社区首页应以封面、预览、重点位播放为主，而不是整屏媒体狂轰。

### 5.4 不把工作流做成“高级用户专属后门”

如果工作流只有专家能看懂，社区会割裂成两层人群。必须保证：

- 普通用户能看结果
- 进阶用户能看方法
- 高级用户能复制和修改

## 6. 对我们自己的产品结论

基于以上竞品，较合理的产品方向是：

- 首页像 TapTap
- 创作者中心与发布体系可参考 LiblibAI
- 工作流广场像 Figma Community
- 作品详情像 Midjourney
- 工作流复制/派生像 Hugging Face Spaces
- 工作流运行与 API 边界可参考 RunningHub
- 工具联动像 Krea
- 精选活动层像 Runway

更具体地说，我们最值得优先设计的不是“更漂亮的首页”，而是这 5 个页面：

- 社区首页
- 视频详情页
- 工作流详情页
- 作者主页
- 发布页

以及这 5 个核心机制：

- 视频与工作流绑定
- 评论与讨论
- 收藏与关注
- 复制与派生
- 精选与活动

## 7. 当前建议的产品优先级

第一阶段先做：

1. 社区首页
2. 视频详情页
3. 工作流详情页
4. 作者主页
5. 发布页

第二阶段再做：

1. 榜单和分区
2. 搜索
3. 关注流
4. 评论增强
5. 工作流派生关系

第三阶段再做：

1. 精选专题
2. 创作活动
3. 创作者认证
